# Agent 私人记忆

## 第一版行为

服务器内置 Python Agent 可以为自己写笔记。只有当前世界与角色的笔记进入模型请求。玩家告诉同伴“东侧仓库是家”时，同伴可以记下原话；自己观察到“有一排箱子，可能是基地”时，可以作为推测记录。是否写笔记由模型决定。当前收到的交流来自已有的本地玩家聊天入口。

系统提示鼓励同伴主动记录会改变下次做法的游戏经验，例如使用某种翅膀通过连续缺口时，哪种走法实际成功了。自然聊天里提到的储物习惯也可以保留。普通游玩可以一条也不写，实际写入以工具回执为准。

| 模型工具 | 用途 |
| --- | --- |
| `memory(command="remember", name=…, description=…, content=…, quote=…)` | 名称是更新用的稳定键，一行描述包含地点或事实。正文与引语可省略。同名写入替换整条笔记。 |
| `memory(command="recall")` | 返回当前私人笔记的名称和一行描述。 |
| `memory(command="recall", name=…)` | 读回正文及写入来源。 |
| `memory(command="forget", name=…)` | 删除该角色在当前世界的指定笔记。 |

引语必须逐字出现在本轮收到的玩家消息中。宿主填写发送者槽位、显示名、消息 ID 和世界会话；笔记所在的世界与角色标识了听者。槽位只在对应会话内有意义。模型生成的描述和正文始终是笔记作者的表述，原话只能证明玩家说过这句话。普通笔记同样带有写入轮次，可表示推测或过去的经历。重新行动时用当前观察确认箱子和物品；容器令牌、动作 ID 和晶塔引用都有自己的生命周期。

## 身份、存储与召回

启动内置模型时，宿主通过现有绑定的 `query_map` 读取 1×1 Tile 窗口，从通过身份核验的观察取稳定的 `worldUid` 和 `characterId`。支持该查询且能取得稳定身份时开放笔记工具。私人笔记存于 Python 宿主仓库的 `.local/agent-memory/<worldUid>/<characterId>/notes.sqlite3`。同一宿主上的相同身份重用同一本笔记，复制世界而保留 UUID 的副本也会命中同一身份；隔离实验应使用单独的笔记根目录。迁移游戏存档到另一台宿主时需要一并迁移相应笔记目录。

写入、替换、删除使用 SQLite 事务。每本最多 32 条，名称、一行描述、正文分别最多 48、120、1500 个字符。满额时仍可更新已有笔记。每次模型请求的运行时数据携带最新的 `privateNotes` 索引，完整正文按名称读取。这个做法适配现有请求压缩和取消机制；代价是每次请求都要计入有界索引的输入成本。读取失败会明确标记。

## 多世界与交流

角色的背包、生命和世界进度按任务从游戏读取。个人笔记记录“谁告诉过我什么”和“我上次做了什么”。已有角色 ID 由世界 UUID 派生，当前产品每世界绑定一个服务器角色；同世界不同角色的存储隔离可以独立验证。

未来加入多同伴时，收件宿主应根据实际投递的事件确认听者和说话者，各听者自行决定是否记下。团队共同约定可以通过交流形成；持久化世界公告需要单独设计发布和更新权限。角色带到其他世界的游戏经验则要先定义跨世界稳定的同伴身份，再决定哪些经验值得迁移。第一版覆盖私人笔记，不自动广播、合并他人笔记或把一次成功升级为通用玩法。客户端玩家模式目前不提供此接口。外部 MCP 接管服务器角色时复用同一本笔记；guide(full=true) 提供内置模型的完整系统提示，guide 和 get_events 返回私人索引。MCP 引语来源仅限本租约已投递的最新有效游戏内玩家消息。默认 external-brain 模式无需初始化内置 LLM。

## 验证

[存储测试](../tests/test_agent_memory.py)覆盖重开、世界及角色隔离、来源、容量、同名修改和删除。[模拟聊天测试](../tests/test_server_ai_agent.py)通过原聊天和工具分发入口记下玩家原话，再新建 Agent 和连接验证召回。两项测试均使用临时目录。真实模型何时主动记笔记，以及真实存档中“返回基地取矿”的完整体验仍待游戏验证。
