# 战斗配装与自卫

战斗配装让 Agent 预先指定角色可使用的主武器、副武器和召唤武器。战斗运行时根据目标距离、武器可用性和资源状态选择具体攻击方式，使角色在采矿或执行其他任务时也能及时自卫。

## 配置

使用 `configure_combat_loadout` 提交完整配置。每个角色包含快捷栏按键、物品类型和当前库存观察 Token。配置写入时会核对 Actor 身份、快捷栏槽位、物品实例和配置冲突，并生成新的配置版本。

配置定义可用武器集合，不会立即改变手持物。战斗开始后，运行时根据目标和当前资源决定选择哪一项。战斗期间配置保持稳定。

## 武器选择

当前选择逻辑围绕原生武器类别：

- **主武器**：优先使用 Agent 指定的主要攻击方式。
- **副武器**：主武器暂时无法有效攻击时，选择可用的备用方式。
- **召唤武器**：用于施放原生召唤物或哨兵，施放后记录仆从来源和实例。

近战范围内优先使用可生效的剑类攻击；远距离可根据弹道和资源使用弓、枪或已适配的法器。武器切换考虑距离余量与连续稳定时间，减少在边界附近频繁换手。弹药或法力不足时，不选择无法完成攻击的武器。

## 采矿自卫

当角色正在使用镐挖矿时，服务器 Reflex 可以识别对角色构成威胁的敌人。战斗入口会先判断是否存在可用武器，再与当前挖掘任务交接。

交接流程包括：

1. 识别威胁并选择候选武器。
2. 请求当前可中断任务结束。
3. 确认旧任务输入释放和原生物品使用周期结束。
4. 重新核对目标、角色身份、配装版本与物品实例。
5. 切换快捷栏并读回实际手持物。
6. 通过原生 ItemCheck 发起攻击并记录命中证据。

角色完成自卫后保留最后选中的武器。被中断的采矿任务由 Agent 根据新观察决定是否重新提交。

## 召唤物生命周期

召唤武器由原生物品使用路径施放。运行时核对原生 Shoot 调用、召唤 Buff 和实际 Projectile 实例，并将仆从与发射武器、Actor 和目标 epoch 关联。

任务结束或取消后，已经生成的原生召唤物继续按 Terraria 自身生命周期活动。命中归因仍要求来源实例和目标关系有效，因此旧任务的回执不会因召唤物后续攻击而被改写。

## 验证记录

该功能分三个阶段完成：拿镐遇敌时切换武器自卫、主副武器根据交战条件切换、战斗期间召唤与补召。各阶段在隔离 Dedicated Server 中验证了原生输入、武器切换、资源条件和命中归因。

具体测试场景与实现历史保留在本文件的 Git 历史及相关战斗专题；当前战斗整体架构见 [战斗系统](COMBAT_SYSTEM_DESIGN.md)，Boss 场景见 [Boss Encounters](R2_E_BOSS_ENCOUNTERS.md)。
