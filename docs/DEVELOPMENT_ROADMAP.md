# 开发路线图

## 项目目标

让 AI 作为 Terraria 世界中的玩家持续行动：理解目标、观察环境、移动和探索、采集资源、使用物品、战斗、建造并与 NPC 交互。项目以完整的游戏任务为目标，逐步提升 Agent 的自主决策和长期执行能力。

## 第一阶段：完成一次有收获的开荒外出

玩家委托是“我们刚开荒，出去找点用得上的东西，拿到后再探一段”。两个自然世界各由外脑自行选择方向、取得一项开荒物资，并越过取物前到过的地段。专服确认背包变化及后续位移。[第一阶段实测](archive/EARLY_GAME_FIELD_TESTS.md#第一阶段完成一次有收获的开荒外出)

## 第二和第三阶段的验收建议

| 里程碑和玩家原话 | 测试初态 | 怎样算完成 | 失败后先查什么 |
|---|---|---|---|
| **2A 遇敌仍能完成外出**。沿用第一阶段原话。 | 第一阶段的两个世界副本、初始铜工具、同一外脑配置，恢复自然敌怪。 | 两个世界各取得一次有效遭遇。专服记录普通敌怪实际构成威胁，角色存活，威胁解除或被甩开后仍执行原委托，最终有物资入包且取物后走入新区域。两项进展中至少一项发生在遭遇之后。 | 按时间对齐敌怪进入威胁范围、自卫或避让、控制权释放、下一次探索动作。查清是没看见威胁、没能脱险，还是脱险后忘了继续。 |
| **2B 自主完成一次地下搜集**。“我们刚开荒，去地下找点用得上的东西。” | 在两个自然世界各从洞外地表出发，使用初始铜工具，关闭非城镇 NPC。两个独立外脑只收到玩家原话。 | 每个世界各自进洞，依据沿途线索选择并取得至少一种有开荒用途的洞内资源。矿物、生命水晶、草药、箱内物资等都可以。用角色轨迹、取物位置和专服背包变化核实；若立即使用物品，也可核对原生使用回执及角色状态变化。取得收获后可结束。 | 按实际经历核对角色看到了什么、选了什么、执行到了哪一步。遇阻时再用路线、地图或交互回执定位原因。 |
| **2C 满包时知道物资留在哪，腾出空间后能拿回** | 在固定专服分别测试路过地面掉落物、对原箱调用 `loot_all`。两种来源都覆盖能全部叠入、只能拿一部分和完全装不下。 | MCP 能读到实收数量，以及因容量不足留下的物品、数量、来源位置和补拿办法。地面提醒同一轮满包只发一次，腾出空槽后可再次触发。每次主动取箱都返回本次结果。脚本腾出空间后，从原处取回余量，以背包和地面或原箱数量核对。 | 先核对实际转移和剩余数量，再检查消息是否送达。箱内剩余还需区分容量限制、原生拾取规则与单次操作上限。 |
| **3A 做出第一个工作台**。“给基地做一个工作台。” | 同一世界、可取木材，分别从背包 7 木材和 10 木材开始，附近没有现成可捡的工作台。 | 两种初态都出现成功制作回执和新工作台。7 木材时补足缺口再做，10 木材时直接制作。数值以本次游戏配方核实。 | 先查有没有读配方，再查缺料计算、取物、制作和产物核验。用“已够”和“差一点”区分游戏知识与采集执行问题。 |
| **3B 按需补料做工具**。“制作一把熔岩镐。” | 用已有规格里的已知基地箱、可采材料及工作站。先比较“库存已够”和“必须补料”两种初态。 | 两种初态各新制一把，绑定角色背包净增一把。缺料场能核对取仓、实采与消耗数量。达到此条件后再标记受控场景通过，开放世界成绩另记。[既有规格与五种库存样本](architecture/R3_B1_GAME_KNOWLEDGE_SPEC.md) | 查第一笔不一致的库存或配方证据，区分用错旧箱记录、漏算材料和原生动作失败。 |

**验证方式。** 2A 在自然运行中没遇敌，记“未覆盖”并保留该次尝试。固定敌怪的中断与恢复测试单列。2B 复用两个地表起点，洞内位置按自然地形核对，并记录取物深度。看到多个目标时，由角色自行决定调查、取物或续行。2C 由固定脚本通过 MCP 复现，依据外脑可见的回执和专服物品变化验收。实际游玩时，是否回仓、存哪些东西、接下来去哪由 Agent 根据玩家委托决定。第二阶段结项依据为 2A、2B 的外脑实测和 2C 的专服回归。第三阶段结项需 3A、3B 分别通过列出的库存初态。

**效率与可靠性。** 外脑通过 MCP 接收玩家原话，不提示工具、坐标或操作顺序。每组保留总尝试数、遇到目标情境的次数、独立成功数和人工提示数。效率沿用首件入包时间、总耗时、取物后新地段位移，另记重复失败的调用。第一阶段的 59–77 秒首次入包、96–116 秒总耗时仅是两个样本。优先修能够在同一初态重放的第一个阻碍，再比同场结果。需要核对游戏知识时，先看已有攻略或原生查询能否回答。

## 当前系统基础

项目已经形成 Python Agent、Lua Runtime、C# CompanionBridge 和 Terraria 原生 Player 组成的执行平台。

目前的主要能力包括：

- 客户端本地玩家控制与独立服务器 AI Player。
- 模型驱动的 Lua 程序执行、API Help 和按需加载的 Gameplay Skills。
- 结构化场景观察、局部语义查询和持久化地图。
- 地面导航、地表图、多尺度搜索、局部地形改造规划。
- 二段跳、翅膀、火箭靴、抓钩、绳索和液体环境适配。
- 原生挖掘、物品使用、库存与装备管理、掉落物收集和物品放置。
- 建筑施工、住宅检查、合成、NPC 服务与经济交互。
- 普通战斗、自卫和 Boss Encounter 任务。

这些能力分布在不同执行路径和后端能力集合中。各模块的接口与支持范围见 [文档索引](INDEX.md)。

## 中长期工作方向

以下方向供后续选题使用，当前安排见页首状态表。

### 1. 真实任务闭环

选择具有连续目标和资源依赖的 Terraria 任务，验证 Agent 能否自主观察、制定计划、组合 API、处理失败并完成目标。重点关注真实模型运行中的任务推进、工具选择、上下文使用和停止判断。

### 2. 探索与长期任务

让 Agent 利用局部观察和持久化地图选择探索目标，逐步形成资源需求、路线、基地和任务进度之间的联系。提升长任务的中断、恢复与跨任务经验利用能力。

### 3. 生存与战斗

将战斗、自卫、装备和资源管理放入连续游玩流程中，验证角色能否根据敌人、生命、武器和环境变化调整策略。

### 4. 世界建设与 NPC 交互

继续完善建筑、住房、商人服务、城镇设施和世界交互，使 Agent 能利用 Terraria 的基础设施支持长期生存和发展。

### 5. 多人环境与稳定性

验证独立 AI Player 与真人玩家共存时的世界同步、角色生命周期、断连恢复和持续运行表现。

## 推进方式

以玩家能够完成的游戏目标组织工作。每个目标先使用现有 Agent、API 和游戏环境建立基线，再根据实际运行结果确定需要改进的环节。

实现完成后，将接口说明、架构变化和有代表性的验证证据更新到对应专题文档。
