# 工程设计

本文记录影响多个模块的核心设计。具体 API、参数和实现细节以对应专题文档为准。

## Agent 与游戏执行的分工

Agent 负责理解目标、选择策略和组织行动。Lua 将多步骤意图编排为程序。原子 API 提供可组合的游戏操作，游戏侧任务运行时推进持续动作。

这种分层让模型关注目标和策略，C# 运行时负责与 Terraria 更新周期、Player 生命周期和原生行为衔接。

## 原生游戏机制

角色移动、碰撞、物品使用、挖掘、放置和实体行为尽量沿 Terraria 原生执行路径完成。预测器用于规划和选择动作，实际游戏状态用于确认执行结果。

## 控制权与任务生命周期

同一个 AI Player 的身体输入由明确的动作或任务持有。任务协调控制动作交接、取消和结束；输入释放与任务终态属于生命周期的一部分。

Server AI 操作绑定 World、Actor、Generation 和 Slot。身份变化时，旧任务随原角色生命周期结束。

## 观察与世界状态

观察数据包含空间范围、采样时间、覆盖情况和对象身份。局部场景、历史地图与实体查询承担不同用途：局部场景描述近期环境，地图保存探索知识，实体查询提供当前候选对象。

模型上下文可以投影和压缩观察，但底层数据仍保留其来源、时间和覆盖语义。

## 客户端与服务器执行路径

客户端本地玩家控制与独立服务器 AI Player 是两套运行路径。客户端路径控制现有本地角色；服务器路径创建并维护独立 Player。两者在 Player 生命周期、同步和能力开放方面分别实现。

## 引擎兼容

依赖 tModLoader 内部实现或 IL 挂钩的功能与具体引擎版本绑定。项目通过引擎配置和指纹管理适配版本，相关变更应结合目标版本原生实现进行维护。
