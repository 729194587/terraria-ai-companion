# 工程原则

本文记录跨模块长期有效的工程约束。具体 API、参数和验证方式以对应专题文档与源码为准。

## Agent 与游戏运行时分工

- Agent 理解目标、观察环境、选择策略并组合能力。
- Lua 用于组织有界程序，不替代游戏侧动作生命周期。
- 原子操作表达单一游戏意图，负责调用原生机制并核验实际效果。
- 需要持续推进的工作由游戏侧任务运行时管理；不要要求 LLM 逐 Tick 驱动。

## 系统安全与游戏风险

系统安全边界必须严格保证：控制权归属、Actor/World/Generation 身份、取消和截止时间、输入释放、动作结果未知时的隔离。

游戏风险是 Agent 决策信息，而不是一律转化成系统拒绝条件。落差、敌人、未知地形、生命损失和导航失败应由策略结合观察处理；不能把预测器或搜索器的局部限制当成 Terraria 规则。

## 原生执行与结果语义

- 使用 Terraria 原生 Player 输入、物理、物品和 Tile 机制；不通过直接修改位置或世界状态伪造游戏行为。
- 网络 I/O、模型推理不阻塞游戏更新；Player、Tile、Collision 访问遵守游戏线程约束。
- 请求已受理、原生函数已调用、输入已释放都不单独证明效果完成。
- 完成状态必须有操作专属的实际效果证据。
- 取消、超时、断连、身份变化和 unknown 保留不同语义；不确定副作用不得盲目重放或自动重试。

## 双执行路径隔离

客户端本地玩家控制与独立服务器 AI Player 是不同执行路径。共享的协议或原子能力不意味着共享 Player 身份、控制权或同步语义。Server AI 的所有读写必须针对绑定 Actor，不回退到真人玩家。

## 观察与记忆

观察具有范围、采样时间、覆盖和截断语义。多次查询不是同一快照；历史地图不等于实时世界状态。未知、过期和未覆盖必须显式保留。

## 引擎兼容性

依赖特定 Terraria/tModLoader 实现或 IL 挂钩的代码必须校验已知引擎版本和指纹。未知环境应明确拒绝启用，不能通过删除检查来掩盖不兼容。
