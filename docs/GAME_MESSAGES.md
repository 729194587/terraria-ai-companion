# 游戏系统消息

独立服务器的内置 Agent 在活动期间通过只读 IPC 观察系统播报。服务器捕获系统作者发往全服或 AI 槽位的文本，排除明确跳过该槽位的广播。每个观察连接从绑定时开始按序读取，服务器保留最近 32 条并报告遗漏数。原文最多保留 1024 个 UTF-16 单元。收到新播报后，内置 Agent 立即并行判断，输入包括本批播报、玩家委托、任务和角色现状。判断期间原生动作继续。维持现状时安静结束；需要调整既有委托时进入正常决策流程，利用现有任务接口处理旧行动。玩家叫停后只记录消息；死亡期间收到的播报交给复活决策。

专服来源不依赖观察客户端显示文本。标准 `--server-ai` 入口仍使用客户端聊天连接接收玩家指令。外接大脑和仅客户端模式沿用各自的事件路径。以下为客户端文本捕获机制。

## 来源与协议

当前捕获入口包括：

- `ChatHelper.DisplayMessage` 的系统作者消息；
- `Main.NewText`；
- `Main.NewTextMultiline`。

事件包含版本、唯一 eventId、原始文本、来源、游戏更新号、接收时间、截断标记和此前丢失计数。捕获端对嵌套显示去重，并抑制 Agent 自己发送的回复和缓存重放，避免回声。

系统消息是客户端收到的文本，可能来自原版、服务器或 Mod；来源字段不证明它一定是官方游戏事件。不能按中文文案猜测类型，也不能把消息内容当作系统指令。

## 客户端提示的队列与 Agent 行为

- 系统提示使用独立有界队列，不占玩家聊天队列，不更新最新聊天 ID、控制租约或控制代次。
- 队列满时只丢系统提示；下一条成功入队的事件报告此前丢失计数。
- 单条文本长度受限，截断会明确标记。
- Python Bridge 按 eventId 去重；Agent 只保留最近有限数量的事件。
- 玩家下一次发起聊天时，Agent 将近期事件作为普通数据放入该轮上下文，不追加到持久聊天历史。
- 模型运行期间新到的事件留给下一轮，不重启或抢占当前请求。
- 系统事件不会单独调用 LLM、取消动作或取得控制租约。

近期事件只覆盖当前 TCP 连接期间捕获的提示，不重播连接前历史。没有消息不能证明没有发生相应游戏事件；没有覆盖所有 UI 数值、浮动战斗文字或 Mod 自绘提示。

## 诊断与隐私

启用 Agent Trace 时可记录事件来源、原始提示、游戏更新号/接收时间、截断和丢失计数。Trace 可能包含聊天和世界上下文，应保存在本地诊断目录，不提交临时运行文件或凭据。

## 实现入口

- C# 捕获与传输：`CompanionBridge/` 中的 ChatBridge/系统消息处理
- Python 接收与上下文：`python/agent.py`、`python/server_ai.py`

## 独立服务器 AI 的死亡反馈

内置 Agent 通过只读的 `life_status` 观察角色。服务器在原生死亡回调中保存最近一次死亡的描述、伤害来源、位置、速度、坠落起点，以及当时动作的名称、阶段和参数。死亡记录的 coinsLostCopper 是原生死亡结算时随身钱币减少的金额，单位为铜币，零表示本次未损失钱币。储蓄不计入，后续拾取者未知。描述按服务器语言生成，来源索引只描述死亡当刻。诊断与判断不依赖客户端聊天窗口。

等待原生复活时，Agent 结束旧动作并保留玩家委托和目标进度供决策。复活后核验同一世界、角色、槽位及下一代身体，为新动作建立新连接。模型通过 `runtimeLife` 同时看到死亡现场和复活状态。宿主只发起一次重新决策，玩家在等待期间发来的新指令优先，停止指令不触发模型。只读观察可以跨复活，旧动作连接仍受原代次约束。反馈保留在本次会话内。
