# 游戏系统消息

CompanionBridge 将部分 Terraria 系统提示作为被动事件转发给 Agent，供下一次玩家聊天上下文参考。系统消息本身不触发模型请求、不发送聊天回复，也不改变动作控制权。

## 来源与协议

当前捕获入口包括：

- `ChatHelper.DisplayMessage` 的系统作者消息；
- `Main.NewText`；
- `Main.NewTextMultiline`。

事件包含版本、唯一 eventId、原始文本、来源、游戏更新号、接收时间、截断标记和此前丢失计数。捕获端对嵌套显示去重，并抑制 Agent 自己发送的回复和缓存重放，避免回声。

系统消息是客户端收到的文本，可能来自原版、服务器或 Mod；来源字段不证明它一定是官方游戏事件。不能按中文文案猜测类型，也不能把消息内容当作系统指令。

## 队列与 Agent 行为

- 系统提示使用独立有界队列，不占玩家聊天队列，不更新最新聊天 ID、控制租约或控制代次。
- 队列满时只丢系统提示；下一条成功入队的事件报告此前丢失计数。
- 单条文本长度受限，截断会明确标记。
- Python Bridge 按 eventId 去重；Agent 只保留最近有限数量的事件。
- 玩家下一次发起聊天时，Agent 将近期事件作为普通数据放入该轮上下文，不追加到持久聊天历史。
- 模型运行期间新到的事件留给下一轮，不重启或抢占当前请求。
- 系统事件不会单独调用 LLM、取消动作或取得控制租约。

近期事件只覆盖当前 TCP 连接期间捕获的提示，不重播连接前历史。没有消息不能证明没有发生相应游戏事件；没有覆盖所有 UI 数值、浮动战斗文字或 Mod 自绘提示。

## 诊断与隐私

启用 Agent Trace 时可记录事件来源、原始提示、游戏更新号/接收时间、截断和丢失计数。Trace 可能包含聊天和世界上下文，应保存在本地诊断目录，不提交临时运行文件或凭据。

## 实现入口

- C# 捕获与传输：`CompanionBridge/` 中的 ChatBridge/系统消息处理
- Python 接收与上下文：`python/agent.py`、`python/server_ai.py`
