# 通用地形挖掘与清障

地形挖掘服务于两类游戏目标：采集指定资源，以及为导航清除必要障碍。两类目标共享原生挖掘执行、工具能力读取、工作位置评估和结果核验，但目标选择与完成条件不同。

## 目标采集

目标采集以矿物组件或指定 Tile 为输入。Agent 可从 `observe_scene` 获取结构化目标，并将目标令牌提交给 `mine_target`。

任务负责：

1. 核对目标身份、Tile 类型和当前状态。
2. 选择符合目标挖掘要求的工具。
3. 评估当前站位可触及的目标。
4. 在需要时导航到新的工作位置。
5. 使用 Terraria 原生挖掘路径逐格执行。
6. 核对目标破坏结果并汇总批次进度。

具备 `server_ai_excavation_v1` 能力时，可按种子目标扩展到同类型四邻接矿物簇。每批最多 18 格，重新观察后继续处理剩余目标。每次游戏更新最多处理 64 个发现队列条目，每个任务最多登记 128 个目标。达到登记边界后仍处理已登记的目标，回执用 discoveryComplete 标明覆盖情况。

## 导航清障

导航在移动路线与局部地形改造之间进行成本比较。需要清除的障碍由当前候选路线产生，不将附近所有可挖 Tile 自动纳入清障。

局部改造规划会评估身体净空、支撑、工具和材料条件，并在独立虚拟地形中估算连续挖掘或搭路后的路线。选定方案后，一次执行一个原生 Tile 操作，读取实际地形变化，再继续规划。

## 工具与成本

挖掘时间受 Tile 的挖掘抗性、当前工具挖掘力、工具类别、装备和增益影响。任务按当前角色与工具状态选择可用工作方式，并在工具或能力变化后重新评估剩余目标。

成本估算用于比较工作位置和路线候选，不替代 Terraria 原生挖掘。实际执行仍受工具、交互范围、Tile 规则和世界状态影响。

## 批次进度

批次回执区分已破坏目标、外部变化、未完成目标和结果未知。子动作历史采用有界记录，同时保留累计挖掘数量、站位移动、放置支撑和搜索进度。

目标 Tile 被破坏只表示采集动作完成，不代表对应掉落物已经进入背包。需要资源数量时，重新观察背包并核对库存变化。
