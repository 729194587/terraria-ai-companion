# 通用地形挖掘与清障

地形挖掘服务于两类游戏目标：采集指定资源，以及为导航清除必要障碍。两类目标共享原生挖掘执行、工具能力读取、工作位置评估和结果核验，但目标选择与完成条件不同。

## 目标采集

目标采集以矿物组件或指定 Tile 为输入。Agent 可从 `observe_scene` 获取结构化目标，并将目标令牌提交给 `mine_target`。

任务负责：

1. 核对目标身份、Tile 类型和当前状态。
2. 选择符合目标挖掘要求的工具。
3. 评估当前站位可触及的目标。
4. 在需要时导航到新的工作位置。
5. 使用 Terraria 原生挖掘路径逐格执行。
6. 核对目标破坏结果并汇总批次进度。

具备 `server_ai_excavation_v1` 能力时，可按种子目标扩展到同类型四邻接矿物簇。每批最多 18 格，重新观察后继续处理剩余目标。每次游戏更新最多处理 64 个发现队列条目，每个任务最多登记 128 个目标。达到登记边界后仍处理已登记的目标，回执用 discoveryComplete 标明覆盖情况。

工作位失败记录按矿脉和出发区的固定世界坐标、角色能力及剩余目标数失效。滚动导航窗口用于当前起点的路线预测。对同一批矿物，同层相距不超过 8 像素的落点共用一次尝试记录。采矿子任务共享失败的开路移动记录，实际清障后可以重新评估。

两次确认采矿进展之间，工作位置搜索和相关子动作最多使用 1800 个游戏更新，其中站位规划与导航共用 900 个更新。原生障碍破坏、角色换位和依赖失效都保留已用预算。回执中的 `workSearchUpdates`、`routeSearchUpdates` 记录本段用量，`stanceAttempts` 记录当前环境下已派发的候选站位。

### 矿物接近决策

单格矿石和矿簇共用 `ExcavationTask`。当前位置能够安全采集时，单格提交原生 `mine_tile`，矿簇提交原有的连续采矿批次。最终支撑矿保留安全下落检查。

需要换位时，搜索比较达到下一次可验证采矿进展的方案。报价包括停稳所需的移动更新、普通方块清除时间、首次目标采矿时间和每格 4 更新的地形改动偏好。清障方案至少再便宜 8 更新以上才会取代完整的无改造方案。搜索还可以派发无改造的远程接近段，在新位置重新观察。

清障路线在第一次破坏前必须预测到工作位。每条候选保留自己的已挖地形，逐格检查工具触及、保护规则和挖后支撑，再模拟下一段移动。直井沿唯一向下的延续分片预测，仍受原生清障范围和 18 格上限约束。到位后重新按真实地形报价。输入释放、目标矿物的逐格破坏证明和普通障碍的破坏计数分别记录。

对于浅埋矿脉，若现有落脚点均够不到矿，规划器还会检查矿脉上方的平地。只有从候选站位模拟向下清障后能安全挥镐，它才派发接近导航；到位后按实际站姿重新检查并执行。角色可以穿过普通草和树干，树根下的支撑仍按原生挖掘规则保护。

回执中的 `approach` 包含最近八次选择的候选成本、预测目标与动作、依赖范围，以及全任务的接近规划耗时、按活动分类的更新数、导航次数、实际清障数和重规划次数。受控与自然场景的同条件实测见[采矿接近对照](architecture/TERRAIN_MINING_RESULTS.md)。

## 导航清障

导航在移动路线与局部地形改造之间进行成本比较。需要清除的障碍由当前候选路线产生，不将附近所有可挖 Tile 自动纳入清障。

局部改造规划会评估身体净空、支撑、工具和材料条件，并在独立虚拟地形中估算连续挖掘或搭路后的路线。选定方案后，一次执行一个原生 Tile 操作，读取实际地形变化，再继续规划。

## 工具与成本

挖掘时间受 Tile 的挖掘抗性、当前工具挖掘力、工具类别、装备和增益影响。任务按当前角色与工具状态选择可用工作方式，并在工具或能力变化后重新评估剩余目标。

成本估算用于比较工作位置和路线候选，不替代 Terraria 原生挖掘。实际执行仍受工具、交互范围、Tile 规则和世界状态影响。

## 批次进度

批次回执区分已破坏目标、外部变化、未完成目标和结果未知。子动作历史采用有界记录，同时保留累计挖掘数量、站位移动、放置支撑和搜索进度。

目标 Tile 被破坏只表示采集动作完成，不代表对应掉落物已经进入背包。需要资源数量时，重新观察背包并核对库存变化。
