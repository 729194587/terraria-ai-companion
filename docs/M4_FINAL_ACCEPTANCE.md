## 1. 阶段目标

M4 的目标不是单纯增加导航
API，而是建立能够支持持续具身执行的空间感知与导航基础。

核心目标：

-   保证空间搜索与物理状态判断正确。
-   让导航动作具备有限的安全恢复能力。
-   支持长距离行程规划与路线接续。
-   感知角色实际运动能力及其变化。
-   建立多尺度空间感知，并复用现有 AI Map。
-   获取环境状态与动态危险信息。

M4 最重要的架构目标是：

**Agent
给出导航目标后，底层能够依据真实空间事实和角色运动能力持续执行；发生可恢复偏差时，可以重新观察、重新规划并继续原有动作，而不是轻易将局部失败升级为目标失败。**

## 2. 六阶段实施结果

### M4.1 --- 搜索正确性与空间/物理契约

**目标：** 修复 StateSpacePlanner
的搜索正确性、状态不变量、启发式与预算退出语义。

**实现：** - Cell 仅作为搜索分区，不再将其视为完整物理状态。 - Label
保留完整 PhysicsState。 - 只有相同物理状态才能参与支配。 -
明确区分目标到达、时间预算耗尽、扩展预算耗尽和局部前沿耗尽。

**验证：** - 搜索定向检查 187 项。 - 几何检查 2018 项。 -
固定自然世界原生对照：新旧版本各完成 24/24 移动段。

**结论：** 在已验证范围内通过。

### M4.2 --- 导航动作内部安全恢复

**目标：** 允许同一导航动作在安全偏差后有限恢复。

**实现：** - 区分路线偏差与不安全失败。 - 释放旧输入后重新观察。 -
确认安全落地与停稳。 - 有界重规划，最多三次恢复。 -
失败边记忆限定于当前导航动作。 -
保留取消、身份变化、未知状态和释放证据契约。

**验证：** - 离线恢复定向测试通过。 - 后续 M4.3
最终包补充了原生位置偏差、动态障碍、空中恢复及取消场景。

**结论：** 结合后续原生补验，在已验证范围内通过。

### M4.3 --- 行程级长距离规划与接续

**目标：** 将多个局部导航过程组织为一个连续行程。

**实现：** - NavigationTripProgress。 - 安全路线前缀接续。 -
当前地形复核。 - 有界退让。 - 重复状态检测。 - 累计搜索与时间预算。

**原生对照：**

  指标           旧版   新版
  ------------ ------ ------
  新规划次数      155    101
  重规划次数      149     95
  目标完成数      5/6    5/6

新版实际接续 59 条路线边，长距离目标包含 1536px 双向跨越场景。

**结论：**
行程接续和搜索开销改善得到验证，但自然世界样本完成率没有提高。仍存在困难地形失败和冷启动性能风险。

### M4.4 --- Mobility Profile

**目标：** 根据角色实际运动能力规划，而不是永久假设固定运动参数。

**实现：** - 运动能力采样及 MobilityProfile。 - 能力版本管理。 - Basic
与已验证的原版 Swiftness。 - 能力变化导致旧计划失效。 -
同一导航动作内安全重规划。 - Swiftness 到期尾效的一帧连续证据处理。

**验证：** - Mobility 定向检查。 - 导航、IPC、M3 恢复回归。 -
原生隔离场景 9 次完成、2 次按预期拒绝。 - 收尾修复补充了快速 Buff
切换及到期帧序重构验证。

**结论：** 已验证运动能力范围内通过。

限制：不支持任意装备、特殊运动效果及第三方 Mod 组合。自然到期验证使用 IL
核对后的帧序重构夹具，不等同于图形客户端自然倒计时实测。

### M4.5 --- 多尺度感知与现有 AI Map 集成

**目标：** 扩展空间观察范围，同时保留近场精细物理事实。

**实现：**

  层级   职责           实现
  ------ -------------- ---------------------------
  L0     近场精细感知   45×29
  L1     实时区域感知   默认 120×68，最多 8192 格
  L2     历史探索记忆   复用 AI Map V1

关键约束： - 保留几何、未知、危险和对象事实。 -
不把未采样区域当作空气。 - 不让 L1 粗粒度信息替代 L0 碰撞与落脚事实。 -
不把区域几何连通解释为身体可达。 - 不创建第二套地图持久化系统。 -
不通过历史地图生成未经验证的导航或采矿承诺。

**验证：** - 16460 项空间与预算检查。 - 2018 项几何检查。 -
Python、导航、IPC、地图定向回归通过。 - 原生区域样本 15/15 完整，L0
外资源可读取，后续导航 1/1 完成并确认释放。

**结论：** 功能验收通过。

限制：区域查询仍采用软预算，存在部分采样和游戏线程耗时尖峰；图形客户端和真实模型尚未验证。

### M4.6 --- 环境状态与动态威胁感知

**目标：** 获取环境状态和动态实体威胁信息。

**实现：**

光照： - 专用服务器无法读取可信原生亮度。 - 明确返回
`lighting.available=false`。 - 不伪造光照数值或照明判断。

动态威胁： - NPC 和敌对弹幕的观察身份。 - 观察 Tick、包围盒和速度。 - 12
游戏 Tick 匀速接触推断窗口。 - 按弹幕额外子步换算速度。 -
明确区分预测接触、无预测接触和不可用。

**验证：** - C# 场景与几何检查。 - 18 项 Python 定向测试。 -
原生服务器观察链路验证。 - 运动接触推断通过离线验证。 - 最终原生复验 15
次区域查询，其中 2 次触及软预算并返回部分采样。 -
后续导航完成并确认输入释放。

**结论：** 按原定能力边界通过。

限制：图形客户端光照、真实移动弹幕接触预测准确率和高密度实体性能尚未验证。

## 3. 跨阶段架构审查

M4 的六个阶段不是独立功能集合，而是共同构成导航与感知执行链。

主要数据流：

1.  L0/L1/L2 提供不同范围和性质的空间事实。
2.  StateSpacePlanner 根据实际物理状态搜索路线。
3.  MobilityProfile 提供已验证的运动能力。
4.  NavigationTripProgress 组织长距离路线接续。
5.  NavigationTask 处理局部偏差、恢复和终止。
6.  NativeNavigation 将结果交给原生游戏执行与验证。

跨阶段约束：

-   导航动作身份和生命周期沿用 M1～M3 契约。
-   取消、输入释放和终态不能由模型自行推断。
-   能力变化必须废弃旧计划。
-   L1 不得越权提供身体可达承诺。
-   L2 历史地图不能覆盖当前实时地形事实。
-   动态危险不能覆盖静态几何事实。
-   未知和部分采样不能解释为安全。
-   所有执行结果必须以实际游戏证据为准。

源码审查未发现足以推翻上述架构的跨阶段契约冲突。

## 4. 验证等级与证据边界

本项目采用以下证据等级：

  等级   含义
  ------ -------------------------
  E1     静态源码、IL 与契约审查
  E2     离线定向测试
  E3     Terraria 原生隔离场景
  E4     图形客户端 Host & Play
  E5     真实模型自主完成目标

M4 的实际证据主要集中在 E1～E3。

已经验证的内容包括： - 搜索正确性。 - 导航恢复。 - 长距离行程接续。 -
Basic/Swiftness 能力变化。 - L0/L1 区域感知。 - AI Map 复用。 -
动态实体观察。 - 原生导航终止与输入释放。

尚未完成： - 图形客户端完整 Host & Play 验收。 - 真实模型自主利用
L0/L1/L2 完成探索目标。 - 真实模型连续执行、恢复和停止的端到端评测。

阶段报告中的定向测试结果不代表全量测试通过。M4
没有统一执行完整全量测试。

GitHub 未提供对应提交的完整 CI
状态记录；本次验收依据是仓库实现、阶段报告及已记录的本地验证证据。

## 5. 遗留风险

### 工程风险

1.  长距离导航在困难自然地形中仍可能失败。
2.  冷启动规划和区域查询存在软预算尖峰。
3.  MobilityProfile 仅支持已验证能力。
4.  第三方 Mod 组合采用保守拒绝。
5.  动态威胁接触预测尚未完成真实移动弹幕验证。
6.  专用服务器无法提供可信原生光照。

### 尚未实现的能力

-   图形客户端实时光照采样。
-   7×7 周围光照指标。
-   自动照明和火把放置策略。
-   任意 Mod 运动能力识别。
-   完整自主战斗。
-   真实模型自主探索及任务闭环。

上述内容不属于本轮 M4 必须补齐的功能，不构成继续扩张 M4 的理由。

## 6. 最终验收结论

**M4 六个实施阶段均已完成，阶段级实现审查结束。**

在已验证范围内，M4
建立了多尺度空间感知、有限运动能力适配、连续长距离导航、安全恢复和动态威胁观察能力。

M4 的工程实现可以冻结，进入 M5。

但 M4 的最终产品级验收仍需在 M5
完成后，通过真实模型与图形客户端进行综合实机测试。

本结论不代表 Agent 已经能够独立完成 Terraria
探索、生存、采矿、建造和战斗。

**最终决策：** - 冻结 M4.1～M4.6。 - 保留已知风险，不扩展新的 M4
阶段。 - 后续进入 M5。 - M5 完成后统一进行真实模型端到端验收。 - PR #25
的合并与项目整体集成验收单独处理。
