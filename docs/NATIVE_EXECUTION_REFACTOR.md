# Terraria 原生执行架构

Terraria AI Companion 将 Agent 决策、游戏动作执行和效果核验分开。Agent 选择目标和策略；执行适配器将动作接入 Terraria/tModLoader 的原生玩家行为；结果层根据游戏状态确认实际效果。

## 执行分层

| 层 | 职责 |
| --- | --- |
| 决策 | 选择目标、工具、位置和动作策略 |
| 执行 | 调用 Terraria 原生 Player、ItemCheck、Tile、Projectile 和 NPC 机制 |
| 适配 | 为 Dedicated Server AI Player 提供 Actor 绑定、游戏线程入口和引擎版本适配 |
| 核验 | 读取世界、库存、实体和输入状态，形成动作结果 |

## 原生执行路径

有合适的原生玩家行为入口时，优先复用该入口。需要专用适配时，保持 Terraria 的核心规则由原生实现执行，项目自身负责提供 AI Actor 上下文和任务控制。

典型路径包括：

- **物品使用与放置**：在绑定 Actor 上下文中进入原生物品使用和 ItemCheck 流程。
- **移动与导航**：通过受控 Player 输入推进自然游戏更新，使用原生碰撞与落脚状态核对规划结果。
- **挖掘**：复用原生工具能力、交互范围和 Tile 破坏事件。
- **战斗**：通过原生物品使用、近战和投射物行为执行攻击，并关联攻击来源与目标实例。
- **背包与装备**：使用 Actor 专属库存操作及原生装备规则。
- **绳索与抓钩**：适配原生 Projectile、附着和攀爬行为，再将结果交接给普通导航。
- **NPC 服务**：调用原生商店、护士、重铸、住房和交易规则。

## Dedicated Server Actor 适配

独立 AI Player 的操作在服务器游戏线程执行。每项动作关联 World、Actor 对象、Generation 和 Player Slot。需要引擎内部方法或 IL Hook 的功能，通过目标 tModLoader 版本和引擎指纹选择适配实现。

原生行为可能依赖 LocalPlayer、Main.myPlayer、鼠标输入或 UI 上下文。Server AI 适配器为当前 Actor 建立受控调用作用域，并在调用后恢复共享状态。各类业务动作仍由自己的任务和执行器管理。

## 任务与身体控制

持续动作由游戏侧 TaskRuntime 推进。任务持有 Actor 的身体控制权，并串行协调导航、物品使用、挖掘、战斗和施工子动作。

任务交接围绕实际输入状态、原生动作周期和 Actor 身份进行。任务终态记录动作结果及输入释放情况；父任务根据自身目标条件汇总子动作结果。

## 原生效果核验

不同操作使用各自的游戏事实：

- 导航：实际位置、速度、支撑和停稳状态。
- 挖掘：目标 Tile 的变化及原生破坏事件。
- 放置：Tile/Object 占地、Frame、支撑和物品消耗。
- 物品使用：原生使用事件、弹药/法力和效果对象。
- 战斗：目标实例生命变化、命中来源及死亡事件。
- 交易：报价、货币、库存和 NPC 服务效果。
- 装备：来源背包槽与目标装备槽的实例变化。

动作回执保留操作状态、证据和执行阶段。诊断日志用于追踪跨层事件，不替代游戏状态核验。
