# 导航系统

导航系统负责把一个局部目的地转化为可执行的 Terraria 原生移动，并在执行过程中持续核对真实角色状态。Agent 选择目的地和整体策略；导航运行时负责地形建模、路线搜索、输入执行、进度监测与落脚确认。

## 入口与目标

服务器侧主要入口：

- `navigate_to_x`：沿水平方向到达指定世界像素 X，目标按玩家碰撞框左边缘解释。
- `navigate_to_landing_region`：到达一个二维落脚区域，区域由玩家左边缘 X 范围和脚底表面 Y 描述。
- `move_input`：执行有界原生方向输入，适合明确的短时动作，不进行路径搜索。

`navigate_to` 是游戏侧持续任务。它可以在多个游戏更新中推进导航、地形改造和内部移动子任务。根任务与子任务由任务运行时管理，详见 [游戏侧任务运行时](M1_TASK_RUNTIME.md)。

## 规划架构

导航采用分层规划：

1. **地形采集与 Surface Graph**：从较大范围地形中提取可站立区域，建立 walk、jump、drop 等候选连接。
2. **局部物理规划**：使用完整位置、速度、着地与跳跃状态搜索短程动作序列。
3. **原生碰撞验证**：在真实游戏世界上验证候选轨迹、身体净空和落脚条件。
4. **逐帧执行**：通过 Terraria 原生 Player 输入推进动作，并将预测状态与实际状态比较。
5. **路线接续**：到达安全检查点后，从新的实际状态继续规划，直到目标完成或任务结束。

Surface Graph 用于组织路线候选，不替代局部物理规划。图边可由多条局部运动实现；已验证连接绑定其起始运动状态、物理参数和轨迹地形签名，地形变化后会失效。

地表图每个根任务最多保留 40,000 个节点，初始采集半径为 24 Tile，按需要扩展，最大半径为 128 Tile。局部物理搜索使用约 192×128 像素窗口，碰撞读取沿用约 45×29 Tile 的局部区域。长距离下降可在已验证落点后交给下一段搜索接续。

## 运动模型

规划器以游戏线程采样的 Player 状态和 Mobility Profile 为输入。Profile 记录有效物理参数、角色尺寸、特殊运动资源和当前支持状态；参数或资源假设发生变化时，相关计划会重新评估。

当前接入的运动能力包括：

- **普通走、跳与下落**：基础状态空间搜索和原生碰撞模拟。
- **浅水涉行**：普通运动角色可在有支撑的浅水中行走，并从水底跳回岸上。
- **Cloud ExtraJump**：仅对已明确建模的原版 Cloud in a Bottle 跳跃使用原生松键/再按下触发，并核对 Active、Available 和跳跃状态。
- **翅膀**：支持已建模的普通非悬停翼型。规划考虑翼时、水平速度参数和原生飞行阶段；实际运行逐帧核对资源。
- **火箭靴**：无功能性翅膀时使用基础推进脉冲模型，跟踪燃料、冷却和输入边沿。
- **抓钩**：在特定高台几何下可执行单钩爪攀升模板。系统选择独立锚点和落脚区，原生钩爪负责牵引，脱钩后再由普通移动模型完成安全落地。
- **绳索**：通过独立的放置、攀爬和下降操作使用原生绳索机制；绳索目前不是 Surface Graph 的通用路线边。
- **液体环境**：地形快照区分实体形状和液体状态；普通导航支持浅水涉行，并对岩浆、蜂蜜、微光及未建模液体保持独立处理。

坐骑、反重力、任意 Mod 运动能力、复杂水中运动和悬停翼型尚未形成通用导航模型。能力发现会记录角色实际装备和资源状态，规划器只使用已有运动模型覆盖的能力。

## 地形改造与路线比较

Phase 3 的局部改造规划为导航增加了有限的反事实评估。规划器可以在独立虚拟地形中估算连续挖掘、放置支撑和组合方案的成本，并与移动路线比较。

虚拟地形只用于结构和成本评估。执行时一次提交一个原生挖掘或放置动作，确认世界变化后重新读取地形并规划下一步。实际移动仍由原生碰撞与物理规划器验证。

资源采集与通路清障共享挖掘执行基础，但目标选择不同：资源采集围绕矿物或指定资源目标；清障围绕形成可通行路线。相关批次机制见 [通用地形挖掘](GENERAL_TERRAIN_EXCAVATION.md)。

## 执行与任务生命周期

导航执行绑定 World、Actor、Generation 和 Player Slot。任务在游戏更新中推进，保留目的地、进展版本、截止时间和子任务状态。

服务器导航根任务以已确认进展续期；内部移动子任务按实际位移和安全停稳检查交接。较长路线可以在安全停稳点返回工作检查点，再从该位置继续同一目的地。搜索分帧执行时不计作角色身体停滞。

每帧执行前检查当前运动参数、地形签名和预期状态；执行后比较位置、速度、支撑、跳跃与特殊资源。路线偏差会触发停止、输入释放和有限重规划。任务终止时汇总实际到达、动作结果和输入释放证据。

## 失败与诊断

导航将以下情况分别处理：

- **已到达**：实际角色状态满足目标落脚区域。
- **局部无路线**：当前搜索范围内没有可验证的接续。
- **未知地形或覆盖不足**：当前观察不足以判断路线。
- **资源耗尽**：节点、时间片或任务预算达到上限。
- **运动状态变化**：装备、Buff、资源或物理参数使计划失效。
- **执行偏差**：实际运动与预测轨迹不符。
- **任务取消或身份失效**：结束当前任务并清理其输入。

这些结果分别对应不同的后续策略。局部搜索失败描述当前搜索范围，不代表整个世界不可达。
