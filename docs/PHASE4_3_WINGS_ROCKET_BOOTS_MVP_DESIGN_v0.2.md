# Phase 4.3：翅膀与火箭靴导航接入（MVP）

**版本：** v0.2\
**状态：** 设计草案，待确认\
**代码基线：** `codex/unified-autonomous-navigation`，提交 `a1f96ec`

## 1. 目标

让导航系统能够使用翅膀进行空中移动，并在没有功能性翅膀时使用火箭靴推进，扩大可达地形范围。

本阶段重点是把已发现的运动能力真正接入导航：能够选择合适的运动方式、发出原生输入、观察实际结果，并在偏离预期时安全处理。

移动速度改善可以是自然收益，但不是本阶段的独立优化目标。

## 2. 当前基础与研究结论

Phase 4.1 已采集功能性翅膀、飞行时间、基础
`WingStats`，以及火箭靴装备和推进资源。当前导航尚未支持这两种能力。

本轮研究确认：

-   翅膀运动涉及 `HorizontalWingSpeeds`、`VerticalWingSpeeds` 和
    `WingGlidingSpeeds`。基础 `WingStats` 不能代表所有实际飞行参数。
-   现有采集时机早于部分翅膀运动钩子的执行。不能通过再次调用 Mod
    扩展钩子来补采参数；应复用原生运行时实际产生的信息，无法可靠描述的特殊行为暂不纳入支持范围。
-   火箭靴是受原生条件限制的短时推进，不是持续飞行。`rocketTime`、冷却和原生触发条件都会影响能否推进。
-   TerraBot
    的空中导航采用路径搜索与实际位置反馈相结合的方式；其"有功能性翅膀时优先翅膀模式"的简化策略适合本阶段
    MVP。

以上是本阶段的技术依据，不要求照搬参考项目的具体算法或常量。

## 3. MVP 要求

### 3.1 翅膀导航

支持使用一类经过验证的原版常规翅膀完成基本空中导航：

-   主动上升和下降控制；
-   空中水平移动；
-   根据剩余飞行时间安排路线；
-   飞行时间耗尽后进入滑翔或安全下降；
-   抵达安全落脚位置后，根据实际状态继续导航。

导航应根据实际位置和运动状态持续修正空中路线，不应只执行一条不再检查的固定轨迹。落脚和任务完成仍以真实碰撞、支撑及目标区域状态为准。

### 3.2 火箭靴导航

在没有功能性翅膀时，允许火箭靴作为短时推进动作参与导航。

需要能够：

-   根据已知资源和状态判断是否值得尝试推进；
-   通过原生输入请求触发；
-   观察原生推进是否真正发生及资源、冷却变化；
-   将推进后的真实状态交回导航继续规划；
-   未触发或实际运动偏离时，不继续执行假定推进成功的旧计划。

火箭靴应复用现有运动规划和执行体系，不作为持续飞行模型。

### 3.3 能力选择规则

本阶段采用简单、明确的策略：

  当前能力状态                   导航策略
  ------------------------------ --------------------------
  有功能性翅膀，且有飞行时间     使用翅膀
  有功能性翅膀，但飞行时间耗尽   滑翔或安全下降
  有功能性翅膀，同时装备火箭靴   仍使用翅膀，不使用火箭靴
  没有功能性翅膀，有火箭靴       可以使用火箭靴推进
  两者都没有                     沿用现有导航

即使翅膀飞行时间耗尽，本阶段也不切换到火箭靴。这是 MVP
的导航策略边界，不代表 Terraria 原生机制不允许这种组合。

## 4. 明确边界

本阶段只实现上述翅膀与火箭靴导航 MVP：

-   不实现翅膀与火箭靴联合推进。
-   不要求支持任意 Mod
    自定义翅膀、特殊悬停或无法从运行时可靠描述的特殊飞行行为。
-   不实现坐骑、钩爪、绳索或液体运动。
-   不修改 G1 第三方 Mod 隔离机制。
-   不重建 Phase 4.1 的能力发现系统。
-   不另建导航任务生命周期；优先复用现有规划、执行、落脚确认和恢复机制。
-   不通过额外调用 `AnyExtraJumpUsable()`、`CanStart()` 或 Mod
    扩展钩子来探测能力或参数。实际触发资格由 Terraria
    原生更新流程决定，并通过运行结果确认。
-   保持现有 Actor、World、Generation、取消和安全恢复边界。
-   Phase 4 全部子阶段完成前，不进行集中图形 Host & Play
    或真实世界验证。

ExtraJump
与翅膀/火箭靴的联合最优规划不属于本阶段目标。若原生输入可能触发其他能力，执行过程必须依据实际状态确认结果，不能仅凭输入推断运动已经发生。

## 5. 验收标准

### 离线与定向测试

1.  能力选择符合第 3.3 节规则，包括翅膀资源耗尽时仍不切换火箭靴。
2.  翅膀模型能够区分主动飞行、滑翔和安全下降。
3.  飞行资源的正常逐帧消耗不会导致每帧规划 Revision 变化。
4.  空中路径检查玩家完整碰撞范围，并遵循现有地形安全与未知状态语义。
5.  火箭靴模型能够表达资源、冷却和触发结果；未确认触发时不会沿用假定成功的预测。
6.  预测偏差能够进入现有安全恢复和重新规划流程。
7.  Phase 1--3、Phase 4.1 和 Phase 4.2 的相关定向回归保持通过。

### 构建与工程回归

-   两个受支持引擎版本构建通过。
-   运行相关运动模型、导航定向测试及既有回归。
-   检查 IPC、Task Runtime、包检查和原生钩子契约。

本阶段的完成声明只覆盖代码、离线和定向验证，不代表已通过图形 Host & Play
或真实世界测试。Phase 4 全部完成后再进行集中实际验证。
