# Phase 4.6：绳索操作与液体感知导航设计 v0.3

**状态：** 设计基线，待实现\
**代码基线：** `codex/unified-autonomous-navigation`，`8c9b82e`\
**目标引擎：** tModLoader `2026.09.3.1`、`2026.08.3.0`\
**前置阶段：** Phase 1--3、Phase 4.1--4.5

## 1. 目标

Phase 4.6 包含两项彼此独立的能力：

1.  **液体感知导航**：导航能识别局部地形中的液体，并根据实际运动轨迹判断直接通过、绕行或进行局部地形改造。
2.  **绳索操作工具**：Agent
    能自主放置、延伸、攀爬和下降绳索，但绳索不进入本阶段的全局导航搜索。

项目目标是自主游戏 Agent。Agent
应能根据探索目标和环境观察，自行决定是否搭建平台、挖掘通道或使用绳索。导航规划器不需要把每一种游戏工具都转化为路径边。

## 2. 液体感知导航

### 2.1 核心原则

**液体不是统一的不可通行
Tile。是否构成导航障碍，应由候选运动轨迹与液体区域的实际交互决定，而不是由"发现液体"或固定面积阈值决定。**

-   小水坑可以直接跳过，不应仅因附近存在水就触发绕行。
-   如果现有运动预测能够保证角色不会进入未建模的液体运动状态，则允许该路线。
-   如果路线需要持续游泳或进入未建模液体状态，第一版不选择该路线。
-   无法安全直接通过时，复用现有导航和 Phase 3
    局部地形改造能力，比较干燥绕行、平台桥和挖掘通道。
-   每次真实挖掘或放置后重新读取环境，不预测或模拟完整液体传播。

### 2.2 环境数据表达

虚拟地形中的实体形状和液体信息必须独立表达。

每格环境至少包含：

  字段       含义
  ---------- -------------------------------------------------
  实体形状   未加载/未知、空气、实心、平台、斜坡、危险实体等
  液体类型   无、水、蜂蜜、岩浆、微光或未知
  液体数量   原生 `LiquidAmount`，范围 0--255

液体数量为 0 时，液体类型不参与判断。不能再因为 `LiquidAmount > 0`
就把整格实体形状覆盖成统一危险字符。

这些数据应是跨线程传递的值快照，不传递 Terraria `Tile`
对象。`PhysicsState`
继续描述角色位置、速度、碰撞体和运动资源，不承载整张液体地图。

### 2.3 运动轨迹与液体交互

现有 `PhysicsSimulator`
是已验证的干燥地面运动模型，不应因为读取到了液体数据就假定它能够预测游泳。

第一版采用保守的模型边界：

-   对每个预测帧检查角色是否进入 Terraria 原生定义的湿润状态。
-   如果普通水接触会使角色进入 `wet`
    状态，当前干燥运动模型不能证明后续轨迹安全，因此拒绝该候选边。
-   如果角色只是从水面上方跳过，且原生湿润检测始终不成立，则可以保留该路线。
-   蜂蜜、岩浆和微光不复用普通水规则；在没有专门验证的运动模型或安全能力前，候选轨迹一律保守拒绝。
-   岩浆使用原生岩浆碰撞检查；本阶段不根据背包里有防护物品就推断当前免疫。
-   对原生碰撞辅助函数可能修改的静态状态，必须保存并恢复，避免污染真实
    Actor 更新。

优先复用原生 `Collision.WetCollision`、`Collision.LavaCollision`
及经固定引擎版本核验的液面查询。不要先自制完整的液体碰撞和液面模拟。

当前 Actor 已经处于
`wet`、蜂蜜、岩浆或微光等未支持状态时，继续沿用现有普通导航拒绝/恢复边界；本阶段不实现游泳或水下脱困导航。

### 2.4 直接通过、绕行与局部改造

导航按以下顺序工作：

1.  **直接通过**：现有运动预测证明角色碰撞体的每帧运动不会进入未支持的液体运动状态。
2.  **干燥绕行**：现有 Surface Graph / State Space
    搜索寻找其他安全落脚路线。
3.  **平台改造**：如果绕行不合适，复用 Phase 3 的有限 Place
    候选，评估在水域上方建立可站立的连续平台通路。
4.  **挖掘改造**：复用 Phase 3 的 Mine 候选，尝试建立干燥替代通道。

不使用固定的水域宽度或面积阈值决定搭桥。应根据候选路线是否安全、平台是否可放置、落脚是否连续以及改造成本进行判断。

平台桥第一版只支持局部、可验证的简单情况。水面高度变化复杂、放置条件不明确、无法确认桥面干燥或落脚不连续时，拒绝该改造候选，继续尝试绕行或报告无法通过。

### 2.5 改造后的液体变化

不实现独立液体流体模拟。

-   每次 Mine / Place 执行后重新读取真实 Tile
    的实体、液体类型和液体数量。
-   如果挖掘使水流入新通道，后续规划必须使用更新后的真实状态。
-   液体数量或类型变化必须使相关地形签名/规划缓存失效。
-   不得仅凭放置或挖掘动作成功就认定液体环境仍然安全。

### 2.6 不同液体的 MVP 策略

  液体   第一版策略
  ------ -------------------------------------------------------------
  水     允许干燥跳跃轨迹；会进入 `wet` 的路线拒绝，优先绕行或搭平台
  蜂蜜   未建模，保守拒绝接触路线
  岩浆   未验证免疫时硬性拒绝接触路线
  微光   特殊环境，保守拒绝接触路线

本阶段不实现游泳、蜂蜜移动、岩浆免疫采集或微光运动模型。

## 3. 绳索操作工具

绳索作为 Agent 独立可调用的操作能力，不作为导航图的边。

### 3.1 放置与延伸

-   使用 Agent 自己库存中的绳索物品。
-   遵循 Terraria 原生放置和延伸规则。
-   针对绳索原生目标位置处理进行专门适配，不直接复用普通放置路径。
-   通过实际 Tile 和库存变化确认成功。
-   对目标被占用、放置距离、库存不足、原生拒绝和取消返回明确结果。

### 3.2 攀爬与下降

-   使用已有绳索沿有限目标向上或向下移动。
-   使用 Terraria 原生附着和攀爬控制，不自建绳索物理。
-   通过真实附着状态、位置和速度确认进度。
-   断绳、阻挡、无法附着、超时、取消或 Actor
    失效时释放输入并返回明确终态。

### 3.3 Agent 组合使用

Agent
可以按"放置---攀爬---重新观察---继续放置"的方式组合基础操作，建设有限高度的绳索通道。

本阶段不要求自动绳梯规划器，不把绳索加入 `navigate_to`
全局路线搜索，也不修改 Phase 3 的局部改造搜索来支持绳索。

## 4. 参考实现

### TerraBot

-   `BotTerrainCommand.cs`：将实体 Tile
    类型、液体类型和液体数量分别导出。借鉴其环境数据分离方式。
-   `BotWaterTraversal.cs`：通过原生湿润/岩浆碰撞、真实落脚和位置反馈处理水中跟随移动。其功能服务于
    Follow 模式，不是通用目的地液体规划；本阶段不移植游泳逻辑。
-   `BotNavigation.cs`：自然落脚点搜索会排除附近液体，体现其保守落脚策略。
-   `BotWideNavigation.cs`：在湿润状态下暂停部分常规导航搜索。
-   `BotCombatLava.cs`：危险液体可进入独立的轨迹风险检查。

### 当前项目

-   `TerrainReader.ReadCell()` 当前在 `LiquidAmount > 0` 时返回统一
    `!`，导致实体形状和液体信息丢失。
-   `NativeMotionWorld.TerrainSignature()` 已经将 `LiquidAmount` 和
    `LiquidType` 纳入签名。
-   `NativeMotionWorld.SafeSweep()` 当前通过 `!`
    将所有液体格作为危险区域。
-   `PhysicsSimulator`
    当前是干燥运动模型；不能将它用于证明游泳轨迹安全。
-   `GameNavigation.OrdinaryRejection()` 当前拒绝角色已经处于
    `wet`、蜂蜜、岩浆或微光等状态。
-   Phase 3 `LocalTerrainPlanning` 已有有限 Mine / Place
    候选，可作为平台桥和挖掘通道的基础。

## 5. 明确不做

-   不把所有液体 Tile 统一标记为不可通行。
-   不以固定面积或宽度阈值决定是否绕水。
-   不实现完整液体流动模拟。
-   不实现游泳、通用水下导航或水下脱困。
-   不实现蜂蜜、岩浆、微光的通用运动模型。
-   不把绳索加入全局导航搜索或 Phase 3 改造候选。
-   不重写 Phase 3 的局部规划架构。
-   不扩展任意 Mod 特殊运动能力；留给 Phase 4.7。

## 6. 验收标准

### 液体感知与导航

-   实体形状、液体类型和液体数量可以独立读取和传递。
-   小水坑场景中，安全跳跃轨迹不会仅因水格存在而被拒绝。
-   预测轨迹会进入原生 `wet` 状态时，不会被干燥物理模型误判为安全。
-   普通水湖能触发干燥绕行或有限平台桥候选，而不是一律硬阻挡或盲目游泳。
-   岩浆、蜂蜜和微光按各自安全边界处理。
-   挖掘/放置后重新读取液体状态；液体变化会使规划缓存失效。
-   不支持的水中起始状态不会被普通导航误接管。

### 绳索工具

-   能放置和延伸绳索，并核对真实 Tile 与库存变化。
-   能沿已有绳索向上和向下移动。
-   Agent 能组合基础操作建设有限绳索通道。
-   失败、取消和 Actor/World/generation 变化不会遗留输入或错误状态。
-   不修改 `Main.myPlayer` 或鼠标全局状态，不污染其他玩家。

### 工程回归

-   两个目标 tModLoader 版本构建通过。
-   现有 Phase 3 Mine / Place、普通导航、Phase 4.2--4.5 回归通过。
-   离线测试覆盖液体分类、轨迹暴露、缓存签名和候选改造。
-   原生定向场景覆盖不同
    `LiquidAmount`、小水坑跳跃、湖面平台、挖掘后液体变化及危险液体拒绝。

## 7. 完成定义

Phase 4.6
完成意味着导航能够区分实体地形和液体环境，并根据真实运动轨迹安全地选择直接通过、绕行或有限地形改造；同时
Agent 获得独立的绳索放置与使用工具。

这不意味着 Agent 已经能够游泳，也不意味着绳索已经成为导航路线类型。
