# Phase 4.6：绳索操作与液体感知导航实现说明

**状态：** 实施计划\
**代码基线：** `codex/unified-autonomous-navigation`，`8c9b82e`\
**目标引擎：** tModLoader `2026.09.3.1`、`2026.08.3.0`\
**配套设计：** `PHASE4_6_ROPE_AND_LIQUID_DESIGN_v0.3.md`

## 1. 实施目标

-   将液体从实体地形分类中拆分出来。
-   让现有导航预测检查候选轨迹是否进入未支持的液体运动状态。
-   复用 Surface Graph 和 Phase 3 局部 Mine / Place 规划处理替代路线。
-   将绳索放置、攀爬和下降作为 Agent 独立操作提供，不接入全局寻路。

## 3. 液体导航实施顺序

### 3.1 先分离环境数据

调整地形快照，使每格能够独立表达：

-   实体形状。
-   `LiquidAmount`。
-   `LiquidType`（仅在数量大于 0 时有效）。

保持快照为值类型/值数组，不跨线程传递 `Tile` 对象。

`TerrainReader.ReadCell()`
不再因液体存在就覆盖实体形状。未知地形、危险实体和液体环境必须是不同信息。

保留 `NativeMotionWorld.TerrainSignature()`
对液体类型和数量的覆盖，并确认任何影响候选路线的液体变化都会使旧搜索或失败边缓存失效。

### 3.2 使用原生碰撞检查候选轨迹

先核实两个目标 tModLoader 版本中的以下方法及其行为：

-   `Collision.WetCollision`
-   `Collision.LavaCollision`
-   `Collision.GetWaterLine`（仅用于水面候选定位；先验证适用条件）
-   `Collision.honey`、`Collision.shimmer` 等静态结果标记

对 `PhysicsSimulator.Predict()`
产生的每个预测帧，检查对应玩家碰撞区域与原生液体状态的交互。

第一版继续使用干燥物理模型，因此：

-   候选轨迹没有进入原生 `wet` 状态时，才可按现有模型继续评估。
-   如果普通水接触使角色进入 `wet`，拒绝该预测边；不模拟游泳。
-   蜂蜜、微光或岩浆接触一律按对应安全边界拒绝。
-   岩浆使用原生岩浆碰撞检查，不根据库存物品推断免疫。
-   检查过程中保存并恢复原生碰撞辅助函数会修改的共享静态标记，避免污染
    Actor 的真实更新。

不要在本阶段新增水中 `PhysicsParameters` 或完整液体物理模型。

### 3.3 复用现有导航搜索

-   Surface Graph / State Space
    的候选边应通过运动轨迹检查，而不是把整格液体作为结构墙。
-   安全跳跃可以跨过小水坑。
-   如果直接路线因液体状态被拒绝，继续由现有搜索寻找干燥绕行路线。
-   不为水域面积设置固定阈值，不单独建设湖泊全局搜索器。

### 3.4 复用 Phase 3 局部改造

在现有 `LocalTerrainPlanning` 基础上处理有限平台桥和挖掘通道：

-   让虚拟地形编辑只修改实体形状，液体信息保持独立。
-   对水面平台桥，先确认目标高度、连续落脚、身体净空和原生放置条件。可验证的简单近水平水面优先；复杂水面或放置结果不确定时拒绝候选。
-   如果 `Collision.GetWaterLine`
    在两个目标版本中适用，可用它辅助确定水面位置；不能依赖未经验证的返回值。
-   平台放置在真实世界完成后，重新读取 Tile 和液体状态，再规划下一项。
-   挖掘后若液体流入新通道，使用更新后的真实状态重新规划；不自行模拟液体传播。
-   不将绳索作为局部改造候选。

需要检查当前 Phase 3
的调用路径：液体导致普通运动边被拒绝时，是否会进入局部 Mine / Place
候选评估。若没有，应以最小改动接入，不重写规划器。

### 3.5 液体安全边界

-   水：只接受不触发未建模湿润运动状态的轨迹。
-   蜂蜜：未建模，拒绝接触路线。
-   岩浆：未验证免疫时硬性拒绝。
-   微光：未建模，拒绝接触路线。

当前 Actor 已处于这些未支持状态时，继续沿用现有普通导航拒绝行为。

## 4. 绳索操作实施顺序

### 4.1 原生放置机制

核实固定版本绳索 ItemCheck 调用链、目标 Y 计算和 `Player.tileTargetY`
的使用位置。当前普通放置路径不能直接放行绳索，因为原生延伸可能依赖共享目标位置状态。

实现绳索专用目标位置适配，复用 Actor 绑定、库存检查、World/generation
校验和操作生命周期。通过真实 Tile 变化及库存消耗确认结果。

### 4.2 原生攀爬与下降

核实 `Player.pulley`、`pulleyDir`、附着检测及 `controlUp` /
`controlDown` 的更新时机。

使用原生攀爬控制，不直接写入
`Player.pulley`，不自建绳索牵引物理。操作应有界，能通过位置、速度和真实附着状态确认进展，并在取消或失败时释放输入。

### 4.3 Agent 接入

提供独立的绳索放置、攀爬和下降操作。Agent
可以通过多次调用组合"放置---攀爬---重新观察---继续放置"。

不增加自动绳索导航，不将绳索接入 `navigate_to` 或 Phase 3 路线成本搜索。

## 5. 定向验证

### 5.1 液体感知与导航

-   相同实体形状、不同液体数量（例如 1、128、255）能被独立表达。
-   小水坑上方的干燥跳跃轨迹可通过。
-   预测轨迹触发 `WetCollision` 时不会按干燥模型误报安全。
-   普通水域可触发干燥绕行或有限平台桥候选。
-   水面平台放置前执行原生预检，放置后核验 Tile、落脚和实际液体状态。
-   挖掘导致液体流入时，旧规划失效并重新观察。
-   蜂蜜、岩浆、微光按边界拒绝。
-   `Collision` 静态标记在预测后恢复，不污染真实游戏状态。

### 5.2 绳索操作

-   有效位置放置绳索。
-   沿已有绳索向上、向下移动。
-   Agent 组合基础操作建立有限绳索通道。
-   目标被占用、无库存、超出距离、断绳、阻挡、无法附着、取消和 Actor
    generation 失效。
-   不遗留输入，不修改 `Main.myPlayer` 或鼠标全局状态。

### 5.3 回归

-   Phase 3 Mine / Place、普通导航和局部规划回归。
-   Phase 4.2 ExtraJump、4.3 翅膀/火箭靴、4.5 钩爪回归。
-   Actor 隔离、输入释放、World/generation 失效。
-   两个目标 tModLoader 版本构建及现有 IPC/IL 契约检查。

## 6. 完成标准

-   液体与实体地形独立表达，数量和类型保留。
-   轨迹评估能区分安全跳过水域与进入未支持的湿润运动状态。
-   导航可复用现有绕行和局部 Mine / Place 能力，不把液体简单视为墙。
-   每次改造后按真实液体状态重新规划。
-   绳索作为 Agent 独立工具可靠工作，不进入全局寻路。
-   双版本构建和相关回归通过。

实现过程中如发现原生碰撞接口在两个目标版本中的行为存在差异，应以隔离原生测试为准，并记录差异；不要用未经验证的自定义液体模拟替代。

## 7. Phase 4.6-A/B 实现记录

- 地形快照的 `rows` 只表达实体形状、危险实体与未知覆盖。独立的 `liquids` 列表以绝对 Tile 坐标返回已读取的非空液体和原生数量。未知格缺少液体项时仍视为未知。普通导航的地形、Surface Graph 和运动签名直接使用独立数据。旧平台下落、挖掘支撑与虚拟改造等只接受干燥结构的路径继续显式使用保守投影。
- 两个固定版本的 `WetCollision`、`LavaCollision` 与两个 `GetWaterLine` 重载的 IL 一致。标准 20×42 玩家碰撞箱经过 `WetCollision` 后使用居中的 10×21 湿润探测区域。原生检测还会考虑斜坡上方格的液体。调用前保存 `Collision.honey` 和 `Collision.shimmer`，在 `finally` 中还原。`LavaCollision` 检查给定矩形且不写共享标记。`GetWaterLine` 含 Tile 写入分支，因此 A/B 的只读预测不调用它。
- 普通水以原生湿润检测为准，检查预测帧起点、终点及最大轴间隔 4 像素的中间采样。岩浆用原生 `LavaCollision` 检查扫过的包围矩形。蜂蜜、微光和未知液体按完整身体扫过区域做保守检查，液面高度换算来自固定引擎的原生碰撞 IL。已有的干燥运动模型和真实湿润状态准入保持有效。
- 局部窗口和已执行路线的签名都包含液体数量与非空类型。变更会使对应 Surface Graph 采样、搜索拒绝缓存和执行失败记忆失效。数量归零时忽略残留类型。隔离夹具只改动液体字段，验证了缓存失效与原实体形状保留。

## 8. Phase 4.6-C 实现记录

- `LocalTerrainView` 的分支只覆盖实体形状，保留实时读取的液体类型与数量。候选仍由 Phase 3 的有界模板产生。模板在身体扫过区域拒绝液体，挖掘继续要求切口的近邻干燥。
- 水面平台候选要求同高干岸、可读的连续普通水面、足够材料、身体净空和逐像素的局部支撑连续性。只接受原版平台 Tile，保留实体锚点、物品、范围、目标占用和 Actor 状态检查。局部工作窗口最多检查 12 列，液面高度差超过 4 像素时拒绝该模板。这是模板的观察和工作边界。
- 小水坑或存在已经验证的完整干燥路线时优先使用现有运动。放置仅执行当前候选的一项，平台方向随内部子动作传递，在首次原生 ItemCheck 前再次核验实时地形、范围和干燥落脚。动态变化导致前置检查失效时复用现有有限重规划。
- 两版固定引擎的 `Player.PlaceThing_Tiles`、`PlaceThing_Tiles_PlaceIt` 和 `WorldGen.PlaceTile` IL 一致。执行复用原生放置、物品消耗和 Tile 核验，不在规划期间调用会放置 Tile 的方法。液面候选用 A/B 已核查的数量换算，未调用带 Tile 写入分支的 `GetWaterLine`。
- 每次确认挖掘或放置后都释放虚拟计划，等待真实落脚并重读当前地形。原有液体签名使变化后的搜索、图和失败缓存失效。局部遇到液体边界且没有可用候选时返回 `navigation_liquid_local_frontier_exhausted`。若进水导致 Actor 的安全落脚无法确认，保留 `unknown` 和输入释放契约。

## 9. Phase 4.6-D 绳索放置与延伸

`place_rope({x, y})` 是独立的 Server AI 原子操作，通过 `server_ai_place_rope_v1` 握手开放给 Lua。坐标为绝对 Tile 坐标。空格放置一节，点击已有原版绳索则延伸到同列下方的首个空格。支持普通绳、藤蔓绳、丝绳和蛛丝绳。优先使用已选中的合格绳索，其次使用 Actor 自己的首个合格快捷栏格。背包材料可经现有库存操作移入快捷栏。

- 两版固定引擎的绳索相关 IL 一致。沿现有 Actor 原生 `ItemCheck` 边界进入 `PlaceThing_Tiles`。原生在 `PlaceThing_Tiles_CheckRopeUsability` 读取点击格，向下查找，写入 `Player.tileTargetY`，后续放置才使用重定向坐标。绳索专用补丁重定向七次读取和一次写入，使用本次操作的 Actor 上下文。非本 Actor 作用域执行原生读写。
- 在准入及实际放置前核对点击格、连续绳段、落点、库存与距离。点击格和实际落点都使用原生放置矩形，单次向下检查最多 16 格。绳索作用域关闭方块替换，仅允许对应 Actor、材料和真实空落点产生放置事件。
- 沿用 World、generation、slot、Actor 对象校验以及原有输入释放和取消。成功回执须包含一次本 Actor 原生放置、实际可用的绳索 Tile 和恰好一件库存消耗，另报告原请求格及是否延伸。原生拒绝、占用、延伸被挡、超距、缺材料和超时均有明确回执，绑定或副作用无法确认时保留 `unknown`。

### 验证范围

隔离夹具验证原生操作期间服务器身份、鼠标与共享 Tile 目标坐标保持原值，并核对非作用域 Player 的读取。超时场景在首帧注入截止计数，以命中原生生命周期的超时分支。generation 失效也由夹具在首帧前注入。

## 10. Phase 4.6-E 原生绳索移动

`move_on_rope({ropeX, targetFeetY, finish, maxUpdates})` 经 `server_ai_move_on_rope_v1` 向 Server AI Lua 开放。`ropeX` 是绝对 Tile 列，`targetFeetY` 是目标脚底的世界像素 Y，向下增大。起点须停稳并与干燥绳柱对齐，头部原生探测格及相邻格至少有两节连续原版绳索。单次最多移动 384 像素、执行 1 到 360 个更新，另有 30 秒服务器动作截止时间。操作可以在 `hold` 后继续从同一绳柱向上或向下。

- `hold` 在目标 ±4 像素内连续两帧确认 Actor 仍附着、松开上下输入且已停稳。`land` 沿绳索下端原生脱离，要求下端有空格、有限落差及正下方完整实体支撑。连续两帧核验已脱绳、停稳、安全着地且脚底距目标不超过 0.5 像素。
- 检查两版引擎程序集中的 `Player.FindPulley` 和 `Player.Update`，相关原生 IL 一致。`PlayerLoader.PostUpdateMiscEffects` 位于上下键重置之后、`FindPulley` 和攀绳运动之前。普通导航的 `PostUpdateRunSpeeds` 边界在攀绳分支之后。使用现有 ModPlayer 回调在正确位置注入 Actor 的 Up 或 Down。原生负责附着、牵引、松键减速和下端脱离。TerraBot 的竖直输入和松键停留提供了对照。
- 复用 Actor 控制租约、单次自然 `Player.Update`、原生安全落脚检查、取消与 IPC 回执。执行中复核连续绳段、身体净空、干燥条件和退出支撑。取消和预算耗尽释放输入，绑定身份变化通过既有身份校验返回 `unknown`。正式路径只写当前 Actor 的受控输入。
- MVP 支持连续、干燥的原版绳柱及正下方实体地面落脚。侧向或跳跃脱离、平台落脚、跨绳柱移动、液体、第三方绳索、图形客户端及多人同步效果待验证或属于后续范围。自动搭绳和 `navigate_to` 接入留在后续阶段。
