# Boss Encounter：专服自主 Boss 战斗

Boss Encounter 是 Server AI 的持续战斗任务。Agent 选择挑战目标和战斗配置；游戏侧任务在每个 Terraria 更新中推进目标追踪、武器执行、威胁躲避、成员归组和战斗结果核验。

当前战斗架构见 [战斗系统](COMBAT_SYSTEM_DESIGN.md)。本文保留 Boss 专用的成员识别、原生命中归因和 Dedicated Server 验证记录。

## 任务架构

普通主动攻击和自卫使用 `CombatController`。显式 Boss 挑战使用同级 `BossEncounterTask`，在一个 TaskSlot 和 actionId 下运行整场战斗。

BossEncounterTask 持有 Encounter 身份、成员集合、当前目标、战术状态和整场战斗证据。底层复用 NativeCombatWorld 的角色绑定、武器选择、原生攻击周期、移动执行和命中采样。

这种划分保留了普通战斗的单目标终态，同时让 Boss 战斗能够处理多成员目标、部件切换和整场胜负。

## 成员身份与归组

NPC Slot 会复用，因此 Encounter 成员使用实例引用，而不是只依赖类型和槽位。引用关联 World、Actor Generation、NPC Slot 和出生 Token；成员刷新时重新核对实例。

不同 Boss 的原生结构并不统一：

- 世界吞噬者通过链式段关系组织成员，断裂后需要重新识别链头、链尾和分支。
- 毁灭者的身体段通过 `realLife` 关联各自根实例；同一世界可同时存在多条实例。
- 双子魔眼是两个独立 NPC，单个成员死亡不代表整场 Encounter 结束。
- 月亮领主的头、手和核心通过出生来源与成员关系关联；核心免疫阶段与真正死亡需要区分。
- 骷髅王的手部成员可被逐个击破，Encounter 继续追踪剩余成员。

当原生关系无法证明成员属于同一场遭遇时，系统保留歧义，不按类型或相邻位置强行归组。

## 命中与胜负证据

战斗证据关联目标实例、生命变化、伤害、攻击来源和 GameUpdate。近战、弹道和召唤物采用各自的原生来源记录。

投射物保存发射时的武器、弹药、所有者、实例和目标 epoch；召唤物记录来源武器及父子 Projectile 关系。NPC Slot 或 Projectile Slot 复用时，旧引用不会自动指向新实例。

成员生命变化、根生命变化和原生死亡事件需要按对应 Boss 的规则解释。Encounter 完成以本场根实例和成员集合的终局证据为依据，世界进度标志只作旁证。

## 威胁躲避

BossEvasion 使用约 48 个游戏更新的局部预测窗口，收集附近 NPC 和弹幕，评估接触、相对运动、光束及平台路径。候选动作复用导航物理模型，比较水平移动、跳跃、下穿平台和已适配的特殊移动资源。

预测器在实际执行后记录位置偏差，并将威胁候选、动作决策和执行结果写入诊断。它是局部决策机制，不是对完整 Boss AI 的确定性模拟。

## 主要实现入口

- `CompanionBridge/ServerIpc/BossEncounterTask.cs`：整场任务。
- `CompanionBridge/ServerIpc/CombatController.cs`：普通战斗与自卫。
- `CompanionBridge/ServerIpc/NativeCombatWorld.cs`：原生攻击、目标身份和命中归因。
- `CompanionBridge/ServerIpc/BossEvasion.cs`：短时威胁预测。
- `CompanionBridge/ServerIpc/TaskRuntime.cs`：任务时钟与生命周期。
- `python/program_tasks.py`：任务提交、查询和取消。

## E0–E4 实施与原生验证记录（2026-11-18 至 2026-11-19）

以下测试均使用复制世界和隔离 Dedicated Server，未调用真实模型。每组结果只代表表中指定的包、引擎、角色配置和场景。

### 原生成员关系探测

| 场景 | 观察结果 | 架构结论 |
| --- | --- | --- |
| 世界吞噬者中段断裂 | 原链包含 1 头、65 身、1 尾；击破中段后形成两条各 33 段的链，旧身体转为新链头/尾，原槽位保留但 Token 改变 | 单个成员死亡不结束 Encounter；断裂后按更新后的双向链重建成员关系 |
| 两条毁灭者同时存在 | 两个根实例分别关联 80 身和 1 尾；击中一条的身体时，该段与对应根生命同步变化，另一根不变 | 通过实例化 realLife 关系区分并行 Encounter，段与根的生命差值只计一次 |
| 一对双子 | Retinazer 与 Spazmatism 分别触发死亡；第一只死亡时世界进度标志仍为 false，第二只死亡后才更新 | 两个成员都属于胜利条件 |
| 两对双子同时存在 | 四个实例同时生成，原生来源不足以证明两两配对 | 保留配对歧义，不根据类型自动配对 |
| 月亮领主 | 头、双手和核心由同一核心出生来源关联；核心进入免疫阶段后仍存活，之后才触发死亡回调 | 部件命中和核心免疫不能被误判为 Encounter 胜利 |

### 生命周期与中断

长时间无人轮询运行、显式取消、断连、死亡、Actor Generation 变化和墙钟超时均有独立隔离场景。记录核对任务终态、攻击计数、Actor 控制位和输入释放。死亡复活后创建新任务 ID，旧任务绑定不复用。

### 复活归队

2026-11-19 的实现增加 `list_teammates`、`set_team` 和 `teleport_to_teammate`，并支持 Boss Encounter 预授权复活归队。专服测试验证队伍读取、失效引用拒绝、死亡中取消、自然复活后的 Generation 更新，以及原 Boss 消失时终止新任务。

其中一次药水执行路径验证角色位置变化 128 像素、药水数量 2→1。该诊断 Player 未接入真实网络。独立 tModLoader 客户端在 Steam 登录检查处退出，因此队友远端所见位置、真实在线队友发现和 Boss 存活时归队后的首次命中仍需多人客户端验证。
