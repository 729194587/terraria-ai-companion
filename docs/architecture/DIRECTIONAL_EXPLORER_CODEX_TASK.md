# 方向探索原型 — Codex Task Brief

## 目标

让 Agent 在没有最终目的地坐标时也能探索：**LLM 选择方向，程序连续推进并观察；出现新发现、局部受阻或达到预算时，将事实交回 LLM；LLM 决定调查、继续或换方向。**

复用现有自主授权、Navigation、任务回执和资源识别。参考 Numen `move.explore` 的职责划分，不移植 Minecraft 寻路实现。

本轮是方向探索与“发现—判断—实际调查—继续”的闭环，不扩展为新的 Frontier、全局探索规划器或基地管理系统。

## 核心设计

### 1. 模型给方向，程序生成短段目标

新增模型可调用的宿主组合工具，以下为拟定调用形式，不是现有 API：

```text
explore({direction: "right", objective: "调查东侧未知区域"})
```

方向支持 `left/right/up/down`。方向是推进偏好，不是持续按键；`down` 不等于垂直挖穿地板，`up` 不承诺角色具备飞行能力。没有当前能力可执行的局部目标就返回事实。

LLM 不提供最终 x/y，也不负责选跳跃点。已知目的地的导航、采集和交互继续使用现有工具；不把所有移动替换成方向探索。

组合执行放在宿主层，复用已有动作和任务调用链。由于当前 AutonomousMode 不执行 Lua，不为这一项强制迁移整个 Agent 到 Lua；旧 Lua helper 可作为复用参考，但同一行程只运行一套探索逻辑。`explore` 是模型工具/宿主组合，不应伪装成服务端已支持的同名原子动作。

### 2. 短段目标如何生成

每段从角色最新实际位置出发，使用新鲜场景的落脚候选或现有导航候选机制，选取符合方向的短距离落点，然后调用已有 Navigation。

- 允许向右时随地形上坡或下坡；方向不等于固定高度直线。
- 上下探索选择实际存在的更高/更低落脚区间，真实可达性由导航判断。
- 落脚区间可能包含角色当前位置。应缩到前进侧或生成其中一个有正向位移的目标，避免提交整个当前平台后立即“已抵达”。
- 保持 Tile、角色左边界像素、脚底高度及落区契约一致；通过现有转换生成参数，不把资源 Tile 当作落脚坐标。
- 本段失败时保留实际原因和已取得的进展。候选不足或本段走不通只说明当前局部尝试受阻，不声称整个方向永久不可达，也不自行转向另一大方向。

复用现有可达性和移动能力判断；不在 Explorer 里重写跳跃高度、墙体可穿越等物理规则。每次组合调用有明确的段数、单段时间和总时间预算；默认值由实现结合现有导航选定并写入文档。短距离不能被等同于短耗时，挖掘/绕行也必须在预算内交还控制权。

### 3. 感知属于探索过程，而不是所有导航的默认行为

出发前建立一次资源基线。探索内部连续执行：

```text
读取当前状态与局部落脚候选
→ 生成当前方向的短段目标
→ 执行原生导航，同时进行有界只读资源感知
→ 短段结束后再次观察
→ 没有新发现且仍有预算：从实际位置生成下一段
→ 新发现 / 局部受阻 / 预算结束：安全收尾，返回主决策轮
```

沿用已实现的途中扫描能力，可以先保留 0.5 秒的最短采样间隔；段间必做检查，不退回“整趟长途结束才观察”。采样器只收集事实和去重，不调用模型，也不选择资源优先级。

有新的、尚未交给模型处理的发现时，不再派发下一段。当前段允许在有界时间内安全收尾，必要时通过现有取消机制取得终态和释放证据，然后返回发现。忽略发现的代价是主决策轮随后启动下一段，而非必须保留旧长导航 ID。

新默认路径不再使用独立 `review_discovery` 模型分支。发现直接进入与探索意图共用上下文的自主决策轮，由它选择继续、调查或换方向。普通目的地导航不自动启动探索扫描和资源打断。

### 4. 资源范围为 120×68 Tile

初始资源观察、途中扫描、段间资源检查采用同一默认范围：角色中心附近 120×68 Tile。精细导航落脚观察可继续使用现有局部窗口，不要求把导航候选层一并扩大。

优先扩展现有 region/resources 读取通路，同时同步 Python 参数校验、能力/结果契约及相关测试。120×68 为 8160 格，在现有 8192 格区域上限内，但这不代表当前就支持该组合，也不保证一次完整扫描的成本。

沿用已有局部资源识别语义，这是有界资源读取，不声称等同渲染画面的真实可见性；不在本轮增加药水或 Mod 感知依赖。资源命中不写入 AiMap，不揭示资源周围隐藏地形。

返回对象身份、精确 Tile 坐标、采样时刻、覆盖范围、实际扫描量和截断/未知信息。分片或截断时不能把未读区域判为空。若需跨 tick 采样，保留各片时间/覆盖信息，不标成单帧结果；测量覆盖与耗时，不以“请求已成功”代替完整扫描。

### 5. 只保留继续探索所需的上下文

沿用会话状态，保留探索意图/方向、正在调查的发现、最近一次探索及调查回执。不要只留下“切换镐”这种最后一步，而丢失为何切换以及原来要往哪走。复用已有上下文/摘要机制；本轮不新建长期目标管理器。

初始观察中已交给模型的对象构成出发基线。后续重复看到同一对象不反复触发发现；新对象、确实变化或未处理发现应能送达主决策。历史资源不能仅因移出扫描范围、截断或未知而判为消失。

“扫描器已见过”与“模型已收到并成功处理”分开：模型请求失败时保留待处理发现，不能被去重吞掉。模型选择继续后，相同未变化对象不使下一次 explore 立刻再次返回。

不要求先识别每个箱子的归属才能探索，也不把所有新看到的箱子断言为天然战利品。该原型不新增基地识别器。

## 返回结果及控制权

保留原生动作回执，在组合层增加探索结果。具体字段按项目约定命名，至少包括：

| 信息 | 含义 |
| --- | --- |
| direction / objective | 本次探索意图 |
| returnReason | discovery、blocked、budget_reached、interrupted、observation_incomplete 或 outcome_unknown 等事实性原因 |
| start / finish / progress | 起止位置、已完成短段和实际位移，注明坐标单位 |
| findings / coverage | 新发现、来源、采样时间、完整性 |
| lastActionResult | 最后子任务的 ID、真实终态、失败原因与输入释放证据 |

`discovery` 和 `budget_reached` 是正常交还控制权，不是探索失败，更不表示全世界探索完成。计划内的收尾/取消不能计为反复无进展；反之，没有实际收益的重复探索仍受现有有界停滞保护约束。

每个子动作继承当前自主授权和角色身份，宿主记录当前子任务 ID。off、玩家接管、死亡、身份变化都终止组合续行，并取消其拥有的正在运行子任务；不能只取消 Python 协程而遗留独立任务。未确认终态和释放时不开始下一身体动作。保留现有模型请求恢复与不确定动作不重放的约定。

## 修改顺序

1. 接通 region/resources 的 120×68 通路和契约，验证范围与扫描覆盖。
2. 实现方向到短段候选的转换，以及宿主 explore 组合执行；把现有扫描/去重/取消逻辑用于它。
3. 在 AutonomousMode 暴露工具和探索结果，收敛重复的 discovery-review 路径，保留轻量连续上下文。
4. 跑定向测试与必要原生场景，交付证据。只读地图仍用 `query_map`，不新增平行的 `observe_world` 总接口。

## 验证与通过标准

### 定向自动测试

- 模型只给方向即可派发短段；每段从更新后的位置生成目标。平地落区包含角色时仍能产生实际前进，左右及上下候选语义正确。
- 候选不是可达性证明。导航拒绝、局部候选为空、预算耗尽都返回准确原因，不在宿主内无限尝试或自行反向。
- 多个无发现短段之间不调用 LLM。途中首次发现进入主决策输入；忽略后继续探索，重复对象不会原地反复打断。
- 调查经过多个动作后，原方向和当前发现仍保留。调查结束可重新选择继续或换方向，不恢复旧任务 ID。
- 120×68 范围正确；在旧 45×29 之外、新窗口内的资源可命中；边界多格对象、截断、未采样区域不产生错误的缺失结论。
- 初始与途中扫描范围一致；初始已知对象不被再次标成途中新发现；失败的模型请求不丢发现。
- 正常发现/预算交还不误触发 no_progress；重复失败仍有界。off、玩家接管、死亡期间无子任务泄漏，旧代次或迟到模型结果不能派发新动作。

优先复用 `tests/test_autonomous_mode.py`、`tests/test_sensed_resources.py`、既有 Lua/SceneLayers/SceneReader 测试以及 `tests/native_autonomy.py`。按改动选择相关定向集合，再运行 `scripts/build-companion.ps1`；不要求全量测试。

### 原生与真实模型分开验收

**原生脚本模型场景**验证真实 Terraria、IPC、移动、采样及释放：从方向指令开始，穿过至少两个短段，在途中发现出发范围外资源；验证返回、继续以及中断，不替代真实模型行为证据。

**真实模型行为验收**观察完整链条：模型选择方向 → 实际移动 → 收到新资源 → 自己判断 → 至少一次真实调查/采集/箱子交互产生可核验变化 → 继续探索或合理换方向。只切换工具不算完成调查。模型可以忽略某次发现，不要求对每个资源都绕路。

真实模型或客户端环境不可用时，明确标为未验收，并给出可复现场景和采集记录方法；不能用脚本模型代替。

记录方向决定、程序生成的短段目标、任务 ID/终态/释放、资源首次发现时刻、主决策输入及后续选择。报告资源扫描耗时/实际扫描量/截断、模型调用次数及探索实际进展；不要只报测试数量。
