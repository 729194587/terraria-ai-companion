# R3 自主探索实现与验收

玩家明确委托探索时，Agent 用 `schedule_exploration` 登记一次有界往返。例如 `{"radiusTiles":24,"maxSegments":12,"allowDig":false}`。半径为 4–64 Tile，外出尝试上限为 1–64 段，整次行程上限为 3600 次游戏更新。Lua 也可通过 `submit_task` 提交 `explore_frontier`。资源沿用实时场景观察和现有交互。[C5 委托规格](R3_C5_AUTONOMOUS_EXPLORATION_SPEC.md) · [C6 地图规格](R3_C6_EXPLORATION_MAP_SPEC.md)

| 阶段 | 实现 | 定向验证 |
|---|---|---|
| P0 边界识别 | 在 AiMap 中提取已知开放格与世界内未知四邻的边界。窗口边缘补读一格，连续边界跨块聚类。 | 固定地图覆盖世界边、裁剪边、封墙和 32 Tile 块缝。只读检查的地图增量为零。 |
| P1 地图记忆 | AiMap 继续作为唯一持久化地形记忆。v2 文件兼容 v1，增加稀疏块版本和观测时间。边界簇按窗口及邻圈版本缓存。 | AiMap 18 项检查及跨进程恢复通过，地图协议 3 项通过。8400×2400 回放中，局部成本查询读 100 格，分片与一次算完选中同一段。 |
| P2 通行与观察 | 在有支撑、身体净空足够的站位间分别搜索去程和返程。干路、浅水、跳跃和可选单格清障按更新数计价。返程须能纯移动完成。按预计新增格数除以往返及观察更新数排序。 | 假时钟和可注入能力覆盖单向井、液体、挖掘报价和派发前新增障碍。缺少回攀能力时无下落候选。 |
| P3 行程与回执 | GoalStore、TaskCoordinator 与 Lua 共用原生根任务。每段结束观察并重算，候选摘要最多三项。已稳定落地的失败入口按方向冷却。新增覆盖、实际返回、安全停稳和释放输入共同决定成功。 | 双岔路第一支受阻后改走第二支，实际地图新增 1 格，重复外出边 0 条，模拟返程 1/1，约 0.78 格/百次模拟移动更新。该夹具暂未显示引入拓扑图的收益。 |

## 导航的职责与后续验收

边界、成本、候选和返程选择均可在没有 Terraria 或导航器的进程中回放。游戏适配层将一段已知走廊和安全落区交给原生执行器；下落前额外检查反向物理轨迹。每段收到完成回执后重新读取玩家位置、脚底高度、支撑及速度。稳定却落错位置时将该方向计为失败，停稳无法确认时结束并报告不确定。最终实绩按本次窗口内从未知变为已知的格数结算。

首版覆盖平坦落区、局部跳落和经授权的有限清障。依赖抓钩的竖井暂缓。当前双岔路与任务夹具分别模拟移动和原生回执，实际落地率、返程率和游戏线程时延仍待测量。

后续专服验收使用同种子、同角色锚点，分别运行双洞口、无回攀能力竖井、途中拆桥和导航停滞场景。记录期望与实际落区、每段输入释放、地图新增量、改选次数及规划帧耗时。要求无返程能力时下落派发数为零，过期路线须重查，错位、超时或未释放均不得报告成功。再用真实模型下达探索及中途改派委托，核对最终回复与原生证据。

## 复核入口

- 边界、通行成本与整程回放运行 `./tests/run_frontier_replay.ps1`。地图迁移与恢复运行 `./tests/run_ai_map_tests.ps1`。
- 使用 Lua 测试环境运行 `python -B -m unittest discover -s tests -p test_ai_map.py -v`。设置 `PYTHONPATH=python;tests` 后，定向运行 `test_m3_program_tasks.M3ProtocolTests` 中四个 `test_frontier_*` 用例，以及 `test_persistent_goal_continues_without_chat`、`test_stop_revokes_pending_goal` 和 `test_uncertain_goal_receipt_fences_next_step`。
- 运行 `./scripts/build-companion.ps1 -OutputPath .local/r3-frontier-build` 已生成 Mod，编译零错误、零警告。
