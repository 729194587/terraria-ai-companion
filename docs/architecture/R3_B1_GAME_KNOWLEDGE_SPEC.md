# R3-B1 · 游戏知识最小闭环实施规格

第一阶段的升级 Skill 与版本化规则通过 `read_skill` 加载。当前使用通用材料规划，按会话原生配方和背包 0–57 号槽位计算。下表保留当时的库存场景，仓库交互、探索与制作的整链验收留待后续阶段。[升级 Skill](../../skills/tool_upgrades/SKILL.md) · [通用规划入口](../../python/lua/modules/material_plan.lua)

依据 [R3-B0 研究](R3_B0_GAME_KNOWLEDGE.md)，首个目标选用 Terraria 1.4.4.9 独立服务器 AI Player 的玩家委托“制作一把熔岩镐”。成功条件是**本次新制一把，且在绑定角色的背包中核实净增一把**。即使原先已有一把，也要按新增数量计算。只问“怎么制作”时可复用同一知识链，验收要求游戏变更次数为零。

## 1. 首批知识和实现边界

| 待补数据 | 最小内容 | 用途与验收 |
| --- | --- | --- |
| 物品标识 | 熔岩镐、狱石锭、狱石、黑曜石的中英文名、别名、实体类型和原生内容键。实现时逐项经注册表校验，区分背包物品与世界 Tile。 | “熔岩镐”和“Molten Pickaxe”解析为同一产物；进入当前会话再解析 typeId。歧义或未命中返回待确认。 |
| 获取与风险规则 | 狱石的候选区域为地狱，常规挖掘要求至少 65% 镐力，在地狱挖除会释放熔岩。黑曜石可在水与熔岩接触处形成，采前须确认实际方块与工具。地狱废屋是寻找地狱熔炉的线索。 | 每条记录含目标键、获取方法、区域或环境条件、工具、风险、适用版本、来源和复查方式。1.4.4.9 的站点来源排除 1.4.5 才加入的匣中熔炉。具体位置由本世界观测提供。 |
| 制作知识入口 | 在现有攻略索引中添加一篇精简的“工具升级与备料”Skill，描述覆盖“熔岩镐、合成、材料缺口”。正文给查询顺序、缺料与缺站分支、入包判据，并指向现有采矿 Skill。 | 玩家只给目标名，模型能够发现入口。索引只含描述，正文按需读取。配方数量在规格和夹具中作为预期值，生产计划从引擎读取。 |
| 世界线索 | 最小输入为已观察的容器锚点、站点或调查入口，带世界/角色身份、坐标单位、来源、采样时点。箱子旧记录可带物品和数量。 | 首版允许从本轮现场观察、同世界历史记录或玩家给出的地点开始。缺线索时产出有界调查目标或说明阻碍；不依赖全图地点库。 |

建议把获取规则保存在版本化只读数据文件中，按内容键精确检索。为控制首版接口数量，可在加载“工具升级与备料”正文时，由宿主从同一数据源附上本案例的少量规则及来源，保持现有 `read_skill({name})` 调用形式。规则不携带坐标、槽位或执行令牌。覆盖范围扩大后再独立分页查询。规则依据见 B0 的 Wiki 对照及版本反例。[B0 知识分类](R3_B0_GAME_KNOWLEDGE.md#3-terraria-wiki-里应保留什么关系)

## 2. 数据流与逐步验收

| 步骤 | 实现行为 | 通过条件 |
| --- | --- | --- |
| 1 · 识别委托 | 区分“讲解”和“制作”；绑定角色、世界、目标产物、新增量及允许的物资来源。利用 `available_skills → read_skill` 读取升级说明，进入采集分支时才需查阅采矿细节。 | 无需玩家点名 Skill 或提供矿坐标。调用记录可追踪知识来源。同一上下文已有正文时可复用。 |
| 2 · 查配方 | `resolve_content → query_recipes({resultType, availableOnly=false, limit, offset})`，对镐和中间物狱石锭各查一次或按需续页。读取产量、材料组、站点、`supported/available/reason` 和空间。 | 原版样本得到镐需 20 锭、铁砧或铅砧；1 锭需 3 狱石、1 黑曜石及地狱熔炉。角色不在站旁也能发现配方。首个空结果、仅查可用配方或截断页均不足以宣告无配方。遇版本差异用原生定义重算；执行不受支持则报告原因。 |
| 3 · 算包内缺口 | 用 `inspect_inventory` 读目标物起始数量及各材料。按“产物 → 中间物 → 原料”展开；中间物先扣库存，再用剩余数量除以每批产量、向上取整。各材料共享同一份可分配库存。 | 得到下节包内基线；站点、工具不计入消耗。材料齐备时跳过开箱与采矿。读取失败保留未知；分页或预算未完成时保留未展开项。 |
| 4 · 核仓与重算 | 仅对允许取用的候选箱按坐标接近。在交互范围内 `open_container → inspect_container`，并读 `inspect_inventory(mode=slots)`。用新鲜容器、源槽、目标槽令牌调用 `withdraw_container_item`，核对转移回执与包内净增。刷新容器令牌并 `close_container`，确认已关闭后再合成。 | 旧记录只给条件估计。箱空、上锁、被占用、不可达或只取出部分时据实重算；不能确定是否已转移时先对账。一次转移只抵扣一次。 |
| 5 · 生成探索目标 | 对仍有正缺口的叶子生成候选，输出“资源、仍需入包数量、区域依据、已知调查起点、下一个观察、停止条件”。先选有现场证据且可安全接近的目标，再选同世界已知入口，最后才选从当前安全落点出发的有限调查。站点缺失另生成“定位/前往站点”目标。 | 24 狱石与 4 黑曜石对应不同环境线索；未知位置只允许提出调查范围。镐力不足转为工具前置，矿格临熔岩且无法确认安全站位时放弃该点。没有安全路线或调查预算用尽时返回剩余缺口。 |
| 6 · 现场采集 | 利用局部场景、语义扫描及 Tile 复查找到新鲜目标，沿现有导航接近，重新检查站位、危险和能力，再提交受支持的采集动作。以拾取后背包读数更新需求。 | 矿格消失而背包不增时，缺口不变。矿点已被他人移除时淘汰旧线索；不依赖 Wiki 或地图粗格签发采矿目标。每次已知净增后可减少或撤销探索目标。 |
| 7 · 分两级制作 | 到可用熔炉旁复查配方和背包，调用现有 `terraria.crafting.make(锭类型, 尚需新增的锭数)`。站在有效砧旁再查配方并制作一把。模块逐批使用新鲜配方令牌。 | 两级各核对 `completedCrafts/producedCount/inventoryVerified`。部分成功只记已确认产量，后续按当前库存重算。输出空间不足、结果未知或取消后不盲目补发。 |
| 8 · 结案 | 将最终背包读数与步骤 1–3 的同角色基线、最终制作回执匹配。 | 仅在回执证明新制一把且包内对应物品净增一把时报告完成。仅找到配方、仅取得 20 锭、拾到现成的镐均不能满足此委托。身份改变或净增无法归因时报告已证实进度与未决项。 |

实现接线以 [技能注册器](../../python/gameplay_skills.py)、[原生配方与可用性](../../CompanionBridge/ServerPlayerRuntime/ActorCrafting.cs#L139)、[制作模块](../../python/lua/modules/crafting.lua)、[容器会话](../../CompanionBridge/ServerPlayerRuntime/ActorContainer.cs#L114) 和 [场景读取](../../CompanionBridge/ServerIpc/ServerSceneReader.cs) 为准。建议把需求计算做成宿主可独立测试的纯函数；模型负责选择来源和行动，Lua 负责按当前授权组合已有接口。单轮预算耗尽时交付有证据的剩余计划，跨轮自动续行沿用 R3-A1 的独立议题。

## 3. 可复算的基线

初态为背包 8 锭、12 狱石、3 黑曜石；假设原生查询与原版配方一致。缺 12 锭，需 36 狱石和 12 黑曜石，包内基线因此为 **24 狱石、9 黑曜石**。已知基地箱旧记录有 5 黑曜石。各行从同一初态分别运行。

| 仓库证据 | 应生成的下一步 | 仍需收集入包 |
| --- | --- | --- |
| 仅有旧记录 | 调查已知且允许取用的箱；保留“若取到 5 则少采 5”的条件计划 | 24 狱石、9 黑曜石 |
| 现场确认并实际取出 5 | 调查可达的狱石与黑曜石来源 | 24、4 |
| 槽位容量只允许取出 2，已核实净增 | 更新库存，按实际可用空间决定整理或采集 | 24、7 |
| 箱已空或已锁，确认没有转移 | 淘汰旧库存估计，保留箱位置与本次调查结果 | 24、9 |
| 背包另一个初态已有 20 锭 | 直接检查砧、空间和目标配方 | 0、0 |

## 4. 交付顺序与发布判定

1. **数据与离线判据。** 先交付版本化规则、升级 Skill 和纯需求计算。表中五种库存样本须逐项精确匹配；另测中英文同义名、版本不匹配、配方页截断和工具/工作站不被扣减。
2. **协议夹具。** 固定世界/角色绑定，验证仅讲解零变更、旧箱记录不抵扣、过期令牌被拒后重读、目标已消失、采后未入包、制作部分完成和 unknown 不重复执行。每个用例记录缺口变化及其凭据。
3. **隔离专服。** 在可控场地设置已知箱、可安全采集的两类材料、可用熔炉和砧。先用固定程序跑完整链、核对原生配方和最终背包，再以相同初态让真实 Agent 仅接收“制作一把熔岩镐”。玩家指令不含攻略名、坐标或配方答案；评测器独立读取初末状态。
4. **验收报告。** 分开报告固定程序与真实 Agent 的成功次数/尝试次数；保存 Skill ID、来源版本、配方分页、初末库存、仓库实际净转移、探索候选及动作回执。有任何一层未运行，就注明该层待验收。固定场地成功只说明这条知识链能转化为实际行动；开放世界长途探索另行评估。
