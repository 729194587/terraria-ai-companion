# R3-C5 · 自主探索架构与实施规格

设计基线为 `codex/r3-b1-material-plan@45195d4`。范围是内置 Python Agent 与独立服务器 AI Player。首个发布切片：玩家开启自主探索并给定一次行程预算；同伴自行选一个调查点，取得可核实的新信息，再回到出发时确认的安全点。玩家途中下达委托时，两类目标共用同一套调度、执行与核验。自主发展、Boss 推进留待后续。下文第 1 节描述现状，其余各节是待实施规格。

## 1. 当前实现及证据边界

| 当前分支源码事实 | 对设计的约束 |
|---|---|
| `Agent.receive → _start_turn → _run` 处理授权聊天；普通游戏公告只缓冲。主循环 0.2 秒超时检查连接。`TaskCoordinator.on_ready` 和 Run 完成回调都可进入 `_wake_task_results`；空闲时按结果序号开通知轮，沿用最近聊天身份，设置 `allow_actions=False`。[Agent](../../python/agent.py#L404) | 已有无聊天唤醒，但缺少独立的目标、行动授权与后续调度。不能用旧 chatId 冒充玩家续令。 |
| Lua Worker 按单程序预算运行；宿主把独立任务交给 `TaskCoordinator`。协调器在发出 start 前分配 taskId，留存 ACK、终态与消费序号，记录限当前连接。换聊天可结束 Run，已受理任务仍可继续。原生 TaskSlot 在游戏线程推进身体任务。[Lua 分发](../../python/lua_runtime.py#L434) · [任务受理](../../python/program_tasks.py#L151) · [TaskSlot](../../CompanionBridge/ServerIpc/TaskRuntime.cs) | 目标可跨多个 Run、程序和 taskId。取消 Run 不能充当身体释放凭据。 |
| 内置 `explore.lua` 在一次调用内扫威胁、选水平候选、用 `navigate_to_x` 移动、复查位置和生命；访问桶和地标随报告返回。场景版能力判断检查 Worker 参数，当前签名不含 `scene_exploration`。[helper](../../python/lua/explore.lua#L89) · [能力判断](../../python/server_ai_contract.py#L55) · [Worker](../../python/lua_worker.py#L151) | 可复用有界局部试探；跨轮选支路、认定地图增量和返程要由宿主负责。 |
| AiMap 常规每隔至少 15 个游戏更新采样视线与照明可及的格子；保存时随角色代次写入，加载时核对世界、角色与尺寸。`query_map` 的概览及区域图读取历史地形；混合粗格须放大。`observe_scene` 给当前几何、对象与覆盖信息；区域采样可能截断。[采样](../../CompanionBridge/ServerPlayerRuntime/AiMapRuntime.cs#L26) · [地图图例](../../CompanionBridge/ServerPlayerRuntime/AiMap.cs#L51) · [持久化](../../CompanionBridge/ServerPlayerRuntime/WorldCharacterPersistence.cs#L48) · [场景](../../CompanionBridge/ServerIpc/ServerSceneReader.cs#L161) | 地图可指引调查，缺少矿种、宝箱内容、访问缘由和有向可通行边。远处场景读取不能计作亲自开图。 |
| 原生导航可在工作检查点重规划，历史支撑参与局部选择；通用 `navigate_to` 能自行开挖或搭路。宿主仅对特定已确认失败提供有界恢复。`resume_task` 当前只对满足危险取消、释放确认等条件的非簇 `mine_target` 创建新任务。[导航根任务](../../CompanionBridge/ServerIpc/AutonomousNavigationTask.cs#L93) · [历史地形](../../CompanionBridge/ServerIpc/ServerAiNavigation.cs#L48) · [导航契约](../../python/atomic_operations.py) · [恢复准入](../../python/program_tasks.py#L292) | 不能把任意导航失败转换成 resume。当前分支另有 `plan_materials` 的背包目标缺口和 `query_item_sources` 的来源查询，可为已授权的资源需求提供线索。[查询契约](../../python/api_documentation.py#L213) |

**历史结果。** [R3-A1 审计](R3_A1_AGENT_AUTONOMY_AUDIT.md) 记录固定 Lua 的 16 条自然地形路线中有 9 条走满六段；当时定向验证 70 项中有两项在导航失败或超时后期待 Lua 返回值，与宿主终止行为不符。该批次没有在本规格中重跑。**待验证推断。** 有向失败记忆可能减少重复撞同一入口；地图边界可能藏在实体墙后。二者的价值都需在同一双岔路场景与当前策略对照，现有结果无法证明持续自主探索成功率。

## 2. P0 · 持久目标、事件与身体所有权

**设计来源。** Numen 的 CompanionLoop 收拢事件，GoalSteward 在 Run 后评估目标、等待有限身体任务并撤销过时评估。采用这两项原则。TerraBot 的 RoamMemory 和 RouteFailureMemory 用位置或有向边、地形签名及到期时间抑制重复尝试，应用于 P1。本项目新增绑定身份、授权代次、回执对账、返程预算与背包/地图谓词，以适配已有原生执行链。[CompanionLoop](https://github.com/Dwinovo/minecraft-numen/blob/ce047ffb08541798ae95757877233e1a4039ff8a/numen-api/common/src/main/java/com/dwinovo/numen/api/brain/CompanionLoop.java) · [GoalSteward](https://github.com/Dwinovo/minecraft-numen/blob/ce047ffb08541798ae95757877233e1a4039ff8a/agent/src/main/java/com/dwinovo/numen/api/agent/goal/GoalSteward.java) · [TerraBot 样本出处](R3_A1_AGENT_AUTONOMY_AUDIT.md#6-numen-与-terrabot-的可借鉴机制)

| 拟新增记录或接口 | 字段与职责 |
|---|---|
| Python GoalStore（SQLite，按 worldUid、characterId 分区） | `Policy` 保存自主模式（默认关）、允许的范围/动作、期限及授权 epoch；`Goal` 保存 id、来源、委托人、优先级、revision、期限、状态、剩余预算、安全锚点、基线、完成谓词与已确认进展。目标可处于待选、执行、待核验、暂停、需对账、完成、取消、失效或受阻。失效例：授权到期或目标地点经充分复查已不存在且委托限定该地点。 |
| `Step`、`Receipt`、待处理事件 | Step 关联 goalId/revision、epoch、绑定代次、操作、目标、预算及预分配 taskId 或同步动作关联号。持久化受理意图后才允许发送；回执以绑定会话、任务或动作 ID、终态版本去重。事务内写回执、更新目标并登记下一次评估，提交后才确认消费。连接内 throughSequence 仅作投递游标。 |
| `enqueue(event) → evaluate(scope) → dispatch(step)` | 单个宿主调度器串行选择目标。聊天、模式开关、Run 结束、任务终态、风险变化、重连及到期产生事件。已有运行中步骤时记下待评估原因；事件合并，每次最多签发一个有界步骤。无新聊天时由持久待办或下一次到期唤醒。无候选时退避至期限、观测变化或玩家输入；空转不请求模型。 |
| Agent / Lua Runtime / TaskCoordinator / C# | Agent 解析委托、调用既有能力并组织回复；目标管理器持有授权、优先级和验证器。Lua 仅组合本步骤允许的读/动作，宿主在每个动作受理处复查授权。协调器负责 ACK、查询、取消与释放；C# 继续裁定实际身体与碰撞。新增内部 goalRunId 和执行上下文，自主轮写 trace；聊天发布仍走原 chatId/reply fence。原结果通知轮保持只读。 |

**完成契约。** 调查目标保存指定区域、允许证据类型、出发时已知格集合、安全返回范围与预算。成功要求取得约定的新格或现场对象调查结果，且返回时同角色安全着地停稳、输入释放。玩家指定采集数量时用同角色实际背包基线和新读数核验；“带回”另加返程条件。目标不明确时请求澄清。预算耗尽但已返回仅记安全结束与实际进展；没有证据则不报成功。

**恢复契约。** ACK 遗失、断连、宿主在发送前后崩溃都可能留下未决意图。先重绑并核对世界/角色、身体所有者、任务可查询性、释放与当前效果；同一意图不自动重放。能证明效果与释放才结算；只能证明身体空闲时可解除占用，旧步骤的效果仍标未知。无法归因的有副作用步骤挂起等人工确认。重启时从库重建待评估队列，先做只读对账；恢复前重验授权期限、安全锚点与预算。不同身份隔离，旧回执只记原目标。

## 3. P1 · 探索机会与逐段闭环

机会索引由 Python 保存，键为世界/角色、类型、Tile 锚点或边界簇。保存来源、采样范围与时点、地形签名、最近实证、关联需求、状态、重查条件。状态为候选、在查、已查、失效、暂不可达；地图仍沿用游戏侧存储。失败单独记为「起点 → 候选落点、失败类别、装备/地形签名、到期时间」。签名改变或冷却到期允许重查。单次超时只记本次预算耗尽；反向边和另一侧入口独立。调查洞口或宝箱只确认观察到的事实，容器内容需另有权限和现场检查。

| 环节 | 输入 → 输出与状态变化 |
|---|---|
| 观察 | 绑定、角色位置/生命、危险、固定窗口的 `query_map(region,cellSize=1)`、局部 `observe_scene` → 带坐标单位、覆盖、截断、游戏更新及来源的快照。确认出发落点与可回撤段；过期或缺测项保留未知。 |
| 发现 | 在地图概览选择近区并放大；从已知可站一侧寻找四邻未知格，合并连续边界。局部场景提供洞口、矿或箱子候选。将已授权资源缺口与匹配的来源/已观测 POI 关联，需求本身不提供坐标。按键合并重复观测。 |
| 选择 | 先过滤越权、致命危险、无新鲜出发落点、处于失败冷却和预算不足以往返的候选。首版确定性排序依次看委托需求匹配、预期新增可见格数、危险等级、估计往返段数、稳定键。风险未知时只考虑已验证一侧的近距观察点。保留次选及排序理由；没有可行外出点则返程或受阻。 |
| 执行 | 以可复查落点作段终点；Tile 地图坐标在适配层转换为世界像素，落脚接口按脚底高度与角色碰撞框定义。默认纯移动，优先使用受支持的 `navigate_to_landing_region`；缺少符合授权的移动能力则受阻。仅在明确允许地形改造时使用可挖可搭的 `navigate_to`。局部水平试探可调用有界 `explore`，前提是其整段动作、范围与预算都可约束。 |
| 更新与核验 | 将 ACK 与终态归入 Step，复读角色与同一窗口地图。仅累计调查区域内首次由未知转为已知的格；重复读取和 region 扫描面积不计。完整、当前且覆盖原坐标的精确复查才可把消失矿点置为失效；读数截断只安排复查。即使 Lua 没有返回值也读取宿主终态和释放证据。 |
| 重规划与返程 | 每段验证后入队重评。确定受阻则冷却该有向入口、尝试次选；调查完成或只剩返程预算时沿已证实的回撤点返回，每段再验可达性。下落等单向地形不能仅凭去程判定返程。安全点被破坏时暂停原返程判据，选择可实证的避险点并报告原目标未完成。 |

## 4. 抢占、停止与生存

停止与外脑租约是执行闸门；闸门打开时，原生保命反应优先，其次玩家委托，最后自主探索。安全中断、玩家新任务与停机都推进 epoch，使旧规划结果无法通过下一次动作准入。具体处理如下。

| 事件 | 身体与目标如何交接 |
|---|---|
| 新玩家委托 | 立即登记高优先级目标，暂停探索，取消已有探索 Run，并请求终止其仍占身体的任务。确认释放后才派发新动作；普通问答可以只读回答。委托结束后仅在自主授权仍有效时重新评估旧探索。 |
| 明确停止 / 关闭自主模式 | 全停先持久撤销自主授权和待续行，取消当前托管动作并等释放；关闭自主模式仅撤销自主目标。迟到回执可对账，不能重开行动。开启新行程需要新授权。原生反射若依然启用，应单列其动作来源。[原生自卫](../../CompanionBridge/ServerIpc/AiAtomicActions.cs) |
| 危险 / 死亡复活 | 本机游戏线程及时自卫；宿主冻结探索派发，记录生命下降、威胁、释放结果。危险解除后读新场景并重新选段；死亡后须确认复活、绑定、装备、位置、锚点与仍可满足的目标。旧落点、矿格令牌与未证实的采集进度作废。 |
| unknown / 外脑接管 | unknown 进入对账；高优先级目标可排队但不能越过占用。外脑接管冻结内脑新动作，按现有租约交接并核查释放；交还后先核对世界与目标。原生明确支持的安全 resume 仍用新 taskId，导航重新观察和选段。 |

## 5. 实施顺序与验收

1. **P0a · 身份、谓词和持久记录。** 先交付 GoalStore、授权 epoch、事件去重、Step 关联与事务化待办；接入假时钟和假身体。验收重复、乱序、崩溃边界和身份隔离。
2. **P0b · 单一唤醒与控制权。** 接 Agent、TaskCoordinator、Lua 动作准入及接管/停止路径，先用一个两步玩家委托跑通“无聊天的第二步”。危险、未知、重启的释放屏障属于本阶段发布条件。
3. **P1a · 机会与仲裁可并行。** 基于 P0 事件与授权契约，一路实现区域差分、POI 索引、排序和有向失败冷却；另一路实现威胁、复活、外脑交还与安全锚点复核。先以只读回放分别验证。
4. **P1b · 有界探索与返程。** 合并两路，接现有落点导航与逐段验证，启用有限行程。明确外出段数、返程余量、运行期限和模型调用上限；耗尽即转返程或挂起。开放世界持续模式由一趟趟有界行程组成，每次均重新准入。

### 离线发布门槛

L0 用临时 SQLite、虚拟时钟和确定性地图测试状态转换；L1 用真实 Agent 调度、Lua Worker 和任务协调器，替换模型与游戏传输，录制每次准入、终态、输入释放及背包/位置。表中均为待建或扩展的夹具。复用 [M3 任务用例](../../tests/test_m3_program_tasks.py)、[地图用例](../../tests/test_ai_map.py)、[局部探索用例](../../tests/test_autonomous_exploration.py)。

| 级别与注入 | 必须观测到的通过条件 |
|---|---|
| L1 一个委托、第一步 ACK 后结束 Run，静默投递终态 | 无新聊天，恰好一次重评并开始第二步；只读通知动作数为零，第二步有独立授权来源。 |
| L0/L1 重复或乱序回执，在提交意图、收到 ACK、写进度前后分别重启 | 一次终态最多一次进展；已受理步骤启动数为一，无法证明受理与否时不补发。跨身份回执不改变当前目标。 |
| L1 探索运行中插入新委托、延迟释放；另测明确全停并重启 | 释放前新委托启动数为零，释放后玩家先行动；全停后即使到期、回执迟到或重启，自主动作仍为零。 |
| L0/L1 双岔路同收益，稳定排序先选左；左入口受阻、右路有新格 | 当前签名与冷却期内不重试左边；实际进入右段并新增至少一格，同区域重复观测增量为零。 |
| L0 旧矿点先给截断场景，再给同坐标完整复查且矿已消失 | 首次保持未知，第二次标失效；无挖掘调用，背包缺口不变。 |
| L1 途中注入威胁、死亡、释放未知和外脑接管（分别回放） | 危险期间无新探索动作；释放未知时持续阻塞。复活或交还后用新位置重评，无旧动作重放，无双重身体占用。 |
| L1 已获得新增格，返程依次注入路过同 X、正确脚底但在移动、正确落地停稳且释放 | 前两次目标未完成，第三次只完成一次。若无新增格或未返回则记录部分进展。 |

**后续实机验收。** 同一复制世界、角色和预算设置双岔路、旧矿点、危险段和可复查的返程点。先用固定策略与真实专服验证几何、开图和释放，再用真实模型仅接收开启探索或玩家委托；两组分别报告成功次数/尝试次数，保留种子、版本、预算、goal/step/task 关联、地图差分、抢占时序和最终位置。独立评测器核对新增格、重复入口、返程、停机后自主动作和未知重放。后两项必须为零；覆盖收益与返程率按场景报告，初次开放世界结果用于建立基线。
