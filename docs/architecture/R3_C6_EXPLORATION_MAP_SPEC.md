# R3-C6 · 自主探索地图架构规格

**建议保留 AiMap 作为唯一持久地形记忆。** 首版只增加块级观测元数据，在角色附近按需计算通行成本和探索边界。一次探索决策选出的是「从哪个已知落点观察哪片未知区域，以及怎样回来」。洞穴拓扑可在出现多条支路时从同一份地图提取。

适用范围为独立服务器 AI Player。第 1 节为对工作区源码的静态核查，基线提交 `45195d4`。第 2 节区分外部结论与项目取舍，第 3～6 节均为待实施、待测量的设计。行程授权、安全锚点和任务生命周期沿用 [R3-C5 探索规格](R3_C5_AUTONOMOUS_EXPLORATION_SPEC.md)。矿物、箱子和掉落物留给现场观察与即时决策。

| Metric map / occupancy grid | Elfes 用规则栅格和概率更新融合不确定传感器读数。[原论文，1989](https://iiif.library.cmu.edu/file/Newell_box00106_fld08178_doc0001/Newell_box00106_fld08178_doc0001.pdf) | 游戏直接提供角色和 Tile 坐标。保留类别栅格，把主要不确定性表达为未见、久未复查和几何信息不足；首版无须估计位姿或逐格占用概率。 |

| Frontier 与信息收益 | Yamauchi 在已知开放空间与未知空间的交界寻找探索目标；Stachniss 等将预期观测收益与动作成本一起评估。[Yamauchi，1997](https://biorobotics.ri.cmu.edu/papers/sbp_papers/integrated2/yamauchi_frontier_explor.pdf) · [Stachniss 等，2005](https://www.roboticsproceedings.org/rss01/p09.html) | 用可见未知格数近似收益，并把边界簇与观察落点分别求解。安全、照明及往返预算约束会主动放弃部分边界，因此不承诺全图覆盖。 |

## 3. 基础地图、成本缓存与过期

| 数据及所有者 | 内容、更新与生命周期 |
|---|---|
| C# 持久基础层 | 保留字节格和原查询。建议从 32×32 Tile 分块起步，每块存 `contentRev, lastSeen(session,tick), knownCount`。每个采样批次仅对有证据的块更新时间；仅当类别变化时递增该块版本及本批全图 `mapRevision`。同位置同值重观不使几何缓存抖动。块时间仅表示块内至少一格被看到。 |
| C# 可重建摘要 | 每块维护各类别计数，推导未知比例及液体存在位。整块合并计数，局部边缘读原格；窗口选区用摘要，边界和窄口回到原分辨率。块摘要可从 v1 字节重建。新存档格式沿用代际校验和原子发布，显式读取 v1、保留全部格、旧块年龄标未知；会话切换后不直接相减游戏 tick。 |
| 临时观测与成本 | 有界窗口内保存精确本次观测掩码、场景编号、采样 tick、碰撞/液量/支撑及危险。由记忆先建候选站位和有向边，只在已揭示范围内以当前局部证据细化。几何读取可服务下一段安全否决，只有原采样规则或确认的自身编辑能持久揭图。动态实体逐次复核。 |
| 缓存依赖 | 几何键含世界/角色、窗口及所有读到的块版本（含身体、跳弧、视线和块外邻格）。报价再绑定角色代际、运动模型、可用装备与资源、工具、改造策略及局部场景签名。排序另依赖起点、返程锚点、预算和照明。采用有上限的 LRU；临时层随场景过期，年龄跨阈值时重算排序，世界或身份更换丢弃运行缓存。 |

**多人变化。** 最小实现依靠重观测、出发前检查和原生轨迹签名。即使类别版本相同，平台坡形变化、闭门或液位上涨也要使现场报价失效。若以后接入可信编辑事件，只用它标记相关已知块及依赖窗口待复查，事件不携带新地形给探索者。未获重新观测前保留历史值并标旧；局部采样缺格或只扫到同块另一端，都不能刷新路线足迹。漏事件时仍在每段检查出发、落区与返程锚点。重查失败则停在已确认安全点，报告具体缺证。

## 4. 通行成本、边界与返程

**动态 Costmap。** 查询结果的基本单位是有向边 `(起始站位与运动资源, 动作, 落区, 到达后资源)`，带上可行性（候选／已局部验证／缺证／已知受阻）、预计游戏更新数和风险原因。先处理硬约束，再对可行路线累加移动、挖掘和观察所需更新；风险与净空余量单列用于过滤或破平。这样既能说清「远多少」，也能说清「为什么放弃近路」。

| 地形或能力 | 报价规则 |
|---|---|
| 天然洞穴、洞室、窄道 | 在已知非阻挡区按角色矩形检验净空，沿支撑生成站位。开阔平地按行走时间报价；洞顶即使很高也不能在空中设落点。窄口先验整段身体能通过，再加换姿、起跳或减速时间。走廊朝向、坡面及平台上下行分别估边。 |
| 实心与镐力 | 默认只移动。允许清障时，仅为已局部观测、够得到且有安全作业站位的身体通道报价。复用工具适配、预计击数、挥击时序及连续挖掘报价，加上移动与停稳时间；镐力不足或保护块拒绝，只有历史 `#` 时返回「需检查材料」。逐次证实改造效果并重算返程。[ActorMining](../../CompanionBridge/ServerPlayerRuntime/ActorMining.cs) · [LocalTerrainPlanning](../../CompanionBridge/Motion/LocalTerrainPlanning.cs) |
| 跳跃、抓钩、翅膀 | 读取当前受支持的运动参数、跳跃次数和剩余翼时。抓钩须有当前入口支持的模板、可用钩、锚点和脱钩落区；翅膀须有覆盖整段的资源。未建模动作标缺证。只为执行入口能验证的动作出价。[MobilityProfile](../../CompanionBridge/Motion/MobilityProfile.cs) · [抓钩模板](../../CompanionBridge/Motion/GrappleClimbPlan.cs) |
| 液体与其他危险 | 历史液体仅提示存在。现场确认有支撑的浅水可按涉水速度出价；深水或液量不明先复查。首版排除岩浆、蜂蜜、微光和模型不支持的运动表面。检查全身及轨迹上的接触伤害、坠落和动态威胁；危险超限直接撤销该段。 |
| 返程 | 从预计到达后的状态向已确认安全锚点单独搜索，计入回程爬升、资源恢复和已发生的地形变化。不可假设反向边存在。要求往返各段有可复查的已知落点、保守时间估计加观察时间及返程余量在预算内；反向能力缺证时只在悬崖上沿观察。 |

**Frontier Detection 与目标选择。**

1. 在行程范围内按块摘要选可能含边界的块及邻块，读取 Tile 精度和一格邻圈。从角色已知站位沿可候选通行的有向边展开；另保留从这些站位可观察的已知空域，容许人在洞底看见侧壁上方的开口。世界外、查询裁剪外和场景未采样各自单列；窗口外相邻格须补读 AiMap 才可判未知。
2. 找出已知开放格与**世界内确为 0 的四邻格**共享的边，按同一可达侧、连续边界聚类，跨块合并。墙与未知的交界不产生普通 Frontier；未知可贡献收益，但不能充当通道、落脚支撑或实体墙。需要挖开的已知障碍进入独立的清障评估。
3. 从已知侧枚举可到达、可返回的候选落区。用近身半径、可信光源及已知遮挡估算由各站位能看到的新增格数 `G`，同一格去重，射线至首个未知即停止。照明缺证时用保守近身范围。保留能看见边界且有完整身体净空、可靠支撑的站位；簇中心在半空、隔墙或积液中时也只提交岸上的落点。
4. 过滤高风险、无返程、超预算和有向失败冷却。相同委托优先级下按单位时间收益 `G / max(1, 去程更新 + 观察更新 + 回程更新)` 排序，再比风险余量、净空和稳定坐标键。例：近井沿预期新增 8 格但井底无法回攀，只评井沿的可见格；侧洞可新增 6 格且 90 更新可往返时，可作为独立候选。两者都缺证时返回「需复查」或「返程」。
5. 每段停稳后比较同坐标、同身份地图，实绩仅计目标范围内首次 `0 → 已知` 的格数。黑暗中没有新增格时，按「有向入口、光照、地形、能力」冷却，变化后可重试。预算截断返回待续游标；本窗口无候选只描述该窗口。

**拓扑的启用条件。** 首版用边界簇即可。若同一洞口反复入选或长途回撤在多个岔路间犹豫，再从按需读取的 AiMap 窗口提取洞穴图。以净空局部变窄处切出入口/通道，把宽阔连通区收为洞室、三向以上连接收为岔路，压缩中间二度节点。结构边保存两端、方向、最窄断面、关联边界簇和依赖块。未知边界标为开放端，竖井按角色能力分别估上下行。用途是合并同支路目标、记下尚未调查的出口、压缩返程路标。每次发布候选仍落回原格和本地导航；只缓存当前窗口，成本节省用第 6 节对照决定。

## 5. 导航与模型接口

首版可在 Python 宿主用有界 `query_map(region,cellSize=1)` 回放静态策略；生产路径把块摘要和只读有界派生查询放在 C#，由宿主提交锚点、范围、预算及允许动作。游戏线程取得绑定快照，按预算分片计算；发布前比较依赖版本。Python 沿用 C5 的行程和失败记录，独立核验绑定与终态。新增只读能力需同步 Schema、能力发现、Python 分发和 C# IPC，旧调用方继续使用 `server_ai_map_v1`。[API 契约](../API_CONTRACT.md)

模型默认只收前三个候选及空结果原因。每项含边界引用、相对方向/地形、预计可新增格、去回程更新、风险、证据年龄、下一步。响应带快照版本、覆盖和截断标记。例如「东侧岔路 · 岸上观察，预计 6 格，去 38／回 45 更新，浅水已复查；南侧竖井暂缓，返程缺锚点」。候选引用仅在对应身份、版本和预算内有效。只有追问局部地形时才展开一个小窗口。

执行下一段先用 L0 的 `landingRegions`、`geometry` 和 `hazards` 复查。把候选匹配至实际落区，传 `navigate_to_landing_region(minPlayerLeftX,maxPlayerLeftX,surfaceY)`，三个数均为世界像素，分别表示碰撞框左边缘范围及脚底高度。远目标拆到当前可复查的中间落区；约束整段轨迹足迹处于已知、策略允许范围，现有入口若无法约束绕行，则需补执行侧检查后才能自动放行。普通落区导航遇门可能开门，严格纯移动策略须传递至执行器；只有允许地形改造才使用可挖搭的 `navigate_to`。到达以同一身份、实际落区、停稳及释放为准，随后重新采样再选段。[动作入口](../../CompanionBridge/ServerIpc/ServerAiNativeActions.cs) · [执行与停稳](../../CompanionBridge/ServerIpc/ServerAiNavigation.cs)

## 6. 实施顺序与离线验收

先跑只读回放建立基线，再接块元数据与增量缓存，随后接局部成本及逐段导航。最后按双岔路对照决定是否启用拓扑摘要。下列均为拟议验收条件；使用固定地图、假时钟、可注入角色能力和可修改的场景快照。

| 阶段及夹具 | 可判定的通过条件 |
|---|---|
| P0 字节地图、世界边、窗口边、块缝、单格洞口、封墙、黑暗 | 与全分辨率人工标注比对，边界集合相同；跨块同一边界只报一次。越界、裁剪和封墙的假边界为零。只读场景即便读到墙后，新增揭示格仍为零。 |
| P1 v1 存档、两角色、局部改造、同值重复采样 | 迁移前后逐格值及旧查询结果一致，年龄未知；跨角色拒读，部分写入保留上一完整代际。只动邻块但穿过轨迹也触发重算；重复同值只更新观测时间，无关块变更不使几何缓存失效。重复窗口的缓存结果须与禁用缓存时一致。 |
| P1 大地图与成本上限 | 在 8400×2400 夹具记录读格、命中数、耗时与峰值缓存。热查询只读请求窗口及已声明依赖；设定每片工作量和缓存容量，超限返回部分结果/游标，恢复后与一次算完的候选一致，淘汰后条目数不超过容量。 |
| P2 洞室低顶、单向落差、浅水/岩浆、软硬墙、翼时耗尽 | 低于身体净空的路线和岩浆落点入选数为零；同收益时有支撑干路优先于更慢涉水。弱镐拒绝硬墙，强镐在授权且报价成功后才产生挖掘边。拆钩或耗尽翼时后失去对应返程边，无法返回的下落派发数为零。 |
| P2 多人拆桥、门闭合、同码坡形变化、L1 截断 | 在选点后、派发前分别注入。没有事件也须由现场复查拒绝失效落点或轨迹；只看到同块远端不能恢复桥的可信度。缺证不计作障碍，未获授权的开门、挖放均为零。 |
