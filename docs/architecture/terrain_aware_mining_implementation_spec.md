# 地形修改感知导航：源码审计与实施计划

日期：2026-11-26  
状态：技术设计与验收规格；尚未实施本轮改动  
目标：Agent 采矿时，方便绕行就绕行；开路更合适时，在动手前预测开路后的完整接近过程，再通过原生动作执行。

## 1. Objective｜目标与边界

以一次 `mine_target` 调用为单位，联合比较现有地形中的接近路线与移除普通障碍后的接近路线。单格矿物与矿簇使用相同的接近决策。模型不负责逐格选择开路位置。

第一轮必须解决：

- 目标就在安全原生触及范围内时，继续直接采集，不增加寻路。
- 可以便宜绕行时，不因为“附近有可挖泥土”而优先破坏地形。
- 需要开路时，在第一次不可逆破坏前，给出到可采矿工作位的完整局部预测方案，包含每次挖掘的触及条件、移动净空和安全支撑。
- 搜索不确定、预算耗尽、动作中断与实际完成分别报告，保留已有逐格证据和输入释放语义。

本轮的新增反事实规划范围是：当前已观测地形中的普通干燥障碍，采用已验证的基础步行、跳跃和受控下落模型。只有通过预测—原生对照测试的动作与形状进入新增分支。已有无改造路线仍可使用其原有运动能力；不因此禁用已有翅膀、钩爪、绳索等路线。

本轮不同时做公开 API 改名/删除、掉落拾取修复、液体工程、任意 Mod 物理支持或整个导航系统重写。已有放置支撑能力保留，但新的挖掘—放置联合搜索不是本轮完成条件。非矿物拆除和家具目标继续保持原有语义。

这是对关键调用链、相关源码和已提交自然场景回执的审计，不是对两个仓库所有模块的全面验证。本轮未重新构建、运行专服或测量性能。下文将源码事实、推断与设计决策分开。引用编号对应文末的固定版本源码索引。

### 2.2 Numen 已验证的机制

`WorkApi.dig` 的公开契约明确包含自动接近：先挖触及范围内的目标，随后移动到能够继续采集的位置；接近过程可在绕行更贵时选择挖掘或搭路。[N1]

关键职责链为：

```text
WorkApi.dig
  → DigCompanionTask：目标、进度、采集循环
  → Arrival.dig / Destination：把矿物变成可交互的到达条件
  → 寻路与执行
  → BlockDigger：通过原生身体操作挖指定方块
```

其任务层和底层挖掘器仍然分层，统一公开入口不等于删除原子挖掘能力。[N1–N3]

本次重点核查了实际寻路代码，而不是只参考历史设计文档：

- `CostModel.breakCost` 使用工具挖掘时间、破坏偏好成本和许可规则；不允许的破坏返回不可用成本，而不是任意用高分绕过限制。[N4]
- `AStar.recentEdits` 将候选路线此前发生的改造写入临时 Overlay；`load` 在这个改后地形上构造后续节点上下文。因此，后续动作会看到前序挖掘留下的空间。[N5]
- 当前实现存在有限历史窗口和有界搜索优化；不能据此宣称它穷举了所有地形变化或保证全局最优。本轮借鉴“目标语义、按动作顺序模拟改造、统一报价”这三个原则，不照搬其状态压缩和预算参数。

### 2.3 我们已经具备什么

|---|---|---|

| `PhysicsSimulator`、`IMotionWorld` | 角色物理状态推进及世界碰撞接口 | 复用运动模型，隔离真实与虚拟地形读取 |

### 2.4 真正需要修正的三处连接

**A. 普通导航与采矿接近并未使用完全相同的决策链。**

普通 `navigate_to` 的 `NativeNavigationWorld.Evaluate` 已会比较移动与局部改造。矿簇 `ExcavationTask.FindWorkPosition` 则先找真实地形里存在的安全工作位，再尝试普通路线；开路主要经 `StartSingle` 进入 `NativeMineTargetWorld`。后者又有自己的接近扫描及 `PreferEdit` / `FindOpening`。这不是“完全没有成本比较”，而是比较机制没有一致地覆盖矿物接近。[T1,T2,T7]

**B. 当前局部出口不等于抵达采矿工作位。**

`LocalEditEvaluation` 使用有限模板，`MaxSteps=4`、`MaxChanges=18`；`OpenExit` 可能只表示存在下一段可前进空间。`LocalEditPlan.NativeVerified` 明确为 false。不能把这种局部结构性结果直接当成“矿物接近全程已经验证”。[T3]

**C. 真实碰撞不是替换地形字符读取就能变成虚拟碰撞。**

`NativeMotionWorld.Move` 使用 Terraria 的 `Collision.TileCollision`、`Collision.SlopeCollision`，其他安全检查也读取真实世界。仅替换一个 `Cell` 回调，不会让引擎碰撞自动看到 Overlay。这是本轮的关键工程边界。[T4]

由 A、B 可推断，现有决策链容易在“尝试真实导航”与“局部挖一格后再看”之间消耗时间。但各部分的具体性能占比尚未实测，不能将所有耗时归因于某一个搜索器。

### 2.5 必须保护的稳定基线

fe6190 已把失败工作位记忆与滚动导航窗口解耦，并在相关环境变化时保留已消耗预算。工作/路线计数在取得确认的采矿进展后可重置，现有回执计数不是整个任务的累计性能指标。[T7]

自然回执中的封闭铅矿是预算耗尽，而不是已证明永久不可达；换位铁矿有 15 格破坏证明和两次到达，但背包只增加 14 个铁矿。新任务不能倒退为根任务超时，也不把破坏数量当作拾取数量。[T9]

## 3. Design｜技术方案与关键决策

### 3.1 保留入口，统一接近决策

继续使用 `mine_target`；`mine_tile` / `MiningRunTask` 继续承担原生执行。不让开路动作递归启动新的独立采矿搜索。

从现有导航局部评估机制中提取或扩展一个共享的“目标接近评估”职责。这里描述职责契约，不要求固定新增类名。

```text
矿物目标 / 普通落脚目标
          ↓
目标条件适配 + 工具/运动能力 + 环境快照
          ↓
共享接近评估
  ├─ 真实地形无改造候选
  └─ 顺序模拟的清障—移动候选
          ↓
同口径完整方案比较
          ↓
现有任务运行时执行一个已复核的动作/安全批次
          ↓
真实观察、效果确认、验证剩余方案
```

单格矿物和矿簇接入同一核心，普通导航复用同一局部改造报价与验证组件。保持普通导航的特殊移动策略边界，避免为了矿物接近重写整条长途导航状态机。

### 3.2 工作目标是条件，不是一个预先固定的站位

采矿到达条件为：

> 在当前候选地形和角色能力下，角色能够安全停稳，并能按已有安全规则对至少一个仍有效的目标矿物产生采矿进展。

目标检查返回能够采集的目标、工具报价、采集覆盖和相关环境依赖。工作位可以原本存在，也可以由本条候选路线的清障创造。

不再仅在“原始地形中已经安全可站”的集合里找终点。可以通过目标谓词或随 Overlay 重新生成候选站位实现，不要求改写所有导航器接口。矿簇到位后仍由现有批次逻辑决定实际采集范围；不得导航顺手清除目标矿石却遗漏目标证明。

### 3.3 有界、按顺序的反事实规划

采用局部宏动作评估/搜索，复用现有动作和模拟器，而非另写一个覆盖全世界的运动引擎。

候选状态至少区分：角色物理状态、这条路线的地形改动、剩余预算以及使用到的运动资源。相同站位但不同障碍移除结果，不能不加区分地合并。缓存的路线/碰撞结果也必须绑定相应的虚拟地形身份。

候选生成围绕达到工作目标所需的身体净空和支撑障碍，而不是枚举附近所有可挖格。基础组合包括：无改造移动段、原地安全清障、清障后的短程移动、已有安全规则支持的受控下降。应支持“挖一段→走进去→再挖一段”，并让较后动作读取较前动作的地形结果。

每一次拟议挖掘都要在它发生前的状态检查：工具能否挖、是否在射程内、该格是否允许清除、移除后当下是否安全。不能先在副本里把整个通道删空，随后才验算最终路线。

搜索按游戏更新分片推进，保留候选游标和预算。现有 18 格批次界限不是“可一次性无校验删除 18 格”的许可。第一轮沿用既有安全改动边界和任务预算，不以调大超时作为实现手段；如某项局部搜索上限确需调整，必须给出实际测量与独立理由。

### 3.4 只读虚拟碰撞与真实性等级

通过现有运动世界接口支持虚拟地形预测，继续使用已有角色运动参数和推进模型。新增适配只对已明确支持、并通过原生对照的地形/动作输出肯定结论；斜坡、半砖、复杂液体或特殊 Mod 行为未被该适配覆盖时，应返回未支持，而不是按空气或普通全砖猜测。

规划不能临时修改 `Main.tile` 后调用原生碰撞再恢复。即使在同一线程，也会污染其他世界读取、帧更新和原生副作用。

明确区分四种信息：

| 结果 | 含义 | 能否据此声称成功 |
|---|---|---|
| 结构可行 | 净空/支撑模板满足条件 | 不能 |
| 完整预测 | 在支持模型内，逐步推演到工作目标 | 不能；可作为经复核后的执行依据 |
| 实际到达 | 真实状态与原生碰撞确认工作位成立 | 只能证明到达 |
| 采矿完成 | 获得原生目标破坏证据及输入释放 | 可以按现有矿物任务契约确认 |

本轮新增矿物清障方案，第一次不可逆清障前必须具有“完整预测”。只有局部出口的方案仍可用于继续搜索；不能用它取代完整预测。更远或未观测地形可以先执行无改造的已验证接近段，再观察重规划，但不据未知后缀进行试探性大范围破坏。

### 3.5 同口径比较绕路和挖路

第一轮采用“获得下一次可验证采矿进展”的滚动目标，而不求整个矿簇的全局最优挖掘顺序。

对能够完成同一工作目标的方案，比较：

```text
预计成本 = 移动更新数 + 清障挖掘更新数
         + 首次目标挖掘更新数 + 地形改动偏好成本
```

前三项按当前角色和工具报价，单位统一为游戏更新。改动偏好成本是“少破坏地形”的策略偏好，不冒充实际耗时。两个完整方案差距很小时优先无改造路线；覆盖更多矿物可以作为近等价方案的次级排序依据。

这样避免把“到一个完整工作位的代价”与“挖开两格、后面还不清楚”的局部代价混比，也避免将不同批次大小的总挖掘时间直接比较造成偏差。到位后仍按现有连续批次采集，不强行一次只挖一格。

危险、不可挖、保护目标和无法确认的落脚属于可行性约束，不是只要绕路足够贵就能突破的价格项。工具更换会改变成本排序；不使用“泥土永远便宜、石头永远绕路”的固定分类规则。

搜索 CPU 时间独立记录，不混入物理动作耗时。直接可采集保持快路径；足够便宜的完整绕路方案可利用清障成本下界提前胜出，避免每次采一格都穷举所有挖路方案。预算内找到的合理完整方案即可执行，不宣称全局最优。

### 3.6 执行与重规划

选定计划后，以现有 `NativeNavigationEdits`、`mine_tile`、`MiningRunTask` 和导航动作执行。当前站位、工具、目标身份、沿途依赖格和危险状态在动手前再次核对。

每次真实地形修改后重新观察。剩余计划与实际结果一致时，可以复用未受影响的后缀，但必须复核；不要求从零重新做整轮候选搜索。实际移动继续由现有原生导航校验。世界变化、角色偏离或工具变化使计划过期时，停止当前控制并从实际状态重新评估。

保留已有取消、绑定失效、部分完成、未知结果及输入释放规则。普通障碍破坏证明与目标矿物证明分开记录；开路动作不能被计为矿簇完成。

### 3.7 预算、失败记忆与结果契约

复用 fe6190 的共享作用域与预算纪律：仅窗口移动不清空失败记录；实际环境变化允许重新评估但不退还已用预算。取得确认的目标采矿进展时，沿用原有进展重置规则，而不是每挖一个障碍就获得新预算。

终态要区分：已完成、搜索预算耗尽、观察不足/模型不支持、已搜索范围内无方案、危险/取消和未知。新增内部原因可以映射到现有公共契约；不得把“采样没搜到”“模型不支持”或“没搜完”映射成全局不可达。只有证据支持时才返回既有 `no_work_position` 语义。

## 4. Implementation｜修改范围与交付顺序

### A. 建立可验证的虚拟运动能力

主要范围：`LocalTerrainPlanning.cs`、`IMotionWorld` 适配边界及必要的定向测试。

完成只读 Overlay 运动预测、逐动作环境依赖和“结构可行/完整预测”的区别。使用受控世界把同一动作序列分别放在虚拟改后地形与实际改后地形运行，比较碰撞、落脚和工具触及条件。

验收门槛：支持范围内预测与原生执行满足现有移动容差和安全条件；未支持形状明确拒绝；规划不会写真实世界。此门槛通过前，不在真实采矿流程启用新增自动清障决策。

### B. 接通共享接近评估与采矿任务

主要范围：`NativeNavigationWorld` 中可复用的评估职责、`NativeMineTargetWorld`、`ExcavationTask`，必要时调整 `LocalEditEvaluation` 和目标条件适配。

将单格矿物与矿簇接近转换成同一目标契约，联合评估绕行与清障路线。支持新创造的工作位与多段清障—移动。旧的局部开路启发式可以作为候选生成器，但不再绕过统一评估自行决定破坏。保持直接采矿快路径与已经验证的安全支撑矿处理。

不得在父任务与每个开路子任务里各自重启同样的完整搜索；对未变的依赖复用候选和后缀。预算、失败记忆与实际证明仍归属于原任务链。

验收门槛：受控场景能明确选择便宜绕行或便宜开路；开路之前已有完整预测；不需要先实际导航失败一次才启动清障评估。

### C. 完成对照验证与回执

主要范围：现有采矿自测、自然场景脚本/fixture、受影响的导航回归与文档。

对 fe6190 与新提交使用相同初始世界副本、配装和任务参数，保留路线选择、预测依赖、实际动作和性能分类统计。提供普通导航受影响范围的定向回归，不以只跑两个矿脉替代共享组件验证。

A、B、C 是依赖顺序，不是三个彼此独立的设计。可以分别提交可构建的 Git commit；具体文件拆分与辅助类型由实现者根据现有组织选择。完整功能验收在 C 后进行。

## 5. Testing｜测试计划与验收

### 5.1 分级顺序

1. 静态契约检查：接口、终态/证明、依赖与预算归属，确认只读规划边界。
2. 构建：使用仓库现有构建入口，记录命令、引擎与包哈希。
3. 定向纯逻辑测试：Overlay、成本、目标条件、失败记忆及搜索有界性。
4. 受控原生测试：先验证虚拟预测，再验证完整任务。
5. 自然世界 A/B 对照及受影响导航/采矿回归。

沿用已有测试设施，包括 `ExcavationSelfTest`、`test_excavation_contract.py`、原生采矿与任务运行时/导航租约检查、`native_natural_mining.py` 和自然导航测试入口。只运行与实际改动相关的测试集；不默认要求全量测试。

### 5.2 关键场景

| 场景 | 预期行为与必要断言 |
|---|---|
| 矿物已安全够得着 | 不启动接近搜索；零额外移动、零普通障碍清除 |
| 便宜绕路、直线有障碍 | 完整绕路胜出；不挖无必要的障碍 |
| 薄泥土墙、绕路明显更贵 | 首次清障前已有完整预测；不先派发明知失败的导航；原生采集完成 |
| 同一地形更换快/慢工具 | 按原生报价改变成本；在设计好的成本交叉场景中改变路线选择 |
| 工作位原本被普通方块占据 | 可以在虚拟清障后形成有效工作位并实际到达 |
| 先挖—移动—再挖 | 后一次挖掘只在预测的中间位置才够得着，顺序不可颠倒 |
| 局部有出口、远端工作位仍不可达 | 不把 OpenExit 当完整路线，不基于它开始新的目标清障方案 |
| 目标矿石同时承担支撑 | 沿用已有安全采矿/下落规则；不得为了统一接口引入回归 |
| 岩浆、落沙、保护结构或挖不动障碍 | 有安全替代就选替代，否则明确拒绝/停止；不把危险当可加价项目 |
| 工具/能力、目标或关键路径格变化 | 计划失效；保留已取得证明和已消耗预算；从实际状态重算 |
| 角色跨 Tile、导航窗口滚动 | 失败记录不被无条件重置，重规划不重新赠送预算 |
| 两条路线同站位但 Overlay 不同 | 搜索和缓存不会将不同可达性混为一谈 |
| 挖掘中取消、子动作刚完成时取消、绑定丢失 | 继承现有完成/部分证明/unknown 规则，输入释放有真实依据 |
| 无完整方案且预算耗尽 | 在根截止前返回预算原因；待处理目标保留，不能假报不可达 |

### 5.3 Fixture 初始化与预测—原生对照

每个受控案例明确初始地形、目标矿物、角色位置/速度/落稳状态、工具/装备、生命和资源。每次从独立副本恢复，不让上次挖开的通道影响下一次。

先在未修改世界上记录规划前后关键格签名，证明规划只读。随后在独立测试世界执行计划产生的原生挖掘与移动，核对每一步的实际地形、身体位置、支撑和目标触及。不能直接删除障碍来冒充执行测试通过。

预测器本身的碰撞对照可以另建“实际改后地形”夹具，但必须与完整任务的真实挖掘测试区分。容差沿用项目已有运动核验规则；不为通过本轮测试单独放宽穿墙、落脚或伤害标准。

自然用例继续使用隔离专服和原有自然世界副本机制。对照双方使用相同敌怪隔离策略；该测试证明地形能力，不延伸为战斗压力下采矿已验证。不得用额外装备或人工开通矿道来掩盖候选选择问题。

### 5.4 自然场景选择

保留换位铁矿 `(2213,519)`、种子 `20261028` 的正常采矿回归，以及封闭铅矿 `(2092,484)`、种子 `1606771215` 的有界终态回归。[T9]

加入或复用已有自然埋藏矿脉中的开路正例，至少一例应能从“完整预测→原生开路→移动→采矿证明”全过程验收；另外复测超过 18 格矿簇的增量批次行为。每个场景只提交一次 `mine_target(cluster=true)`，单格模式另有受控对照。

封闭铅矿成功采集不是硬性条件。如果它仍无已验证完整路线，正确的预算终态可以通过可靠性回归，但不能被算作本轮开路能力的成功正例。

### 5.5 记录什么，怎样判断是否更好

现有逐格证明与输入释放证据不变。补充最小必要的结构化诊断：

- 选择的是无改造还是清障路线；两种候选的完整性、成本分解及选择原因。
- 第一次清障前预测的工作目标、动作序列摘要、环境/能力依赖；预测不标记为实际成功。
- 全任务累计规划 CPU 时间、最大单片耗时，及规划/移动/普通障碍挖掘/矿物挖掘/等待的游戏更新计数。
- 已派发和失败的导航次数、计划与实际清除普通方块数、重规划次数、最终目标证明与 pending。

不要把末尾被进展清零的 `workSearchUpdates` / `routeSearchUpdates` 当作全任务总耗时；不要把绝对游戏更新编号当作任务持续时长。

相同初始条件的受控性能场景至少重复三次，汇报中位数和范围。先判行为正确，再判效率，不编造没有实测支持的固定提升百分比。

通过标准：

1. 上表关键正确性场景通过，预测与执行证据分离。
2. 薄墙正例在第一次清障之前已有完整预测，清障不依赖一次实际导航失败触发。
3. 便宜绕行案例零不必要清障；直接可采集案例保留快路径。
4. 对基线本就能完成的开路案例，至少展示一项明确的接近效率改善，并同时报告规划开销；不能只展示成功率、隐藏严重的规划或整体耗时退化。
5. 对基线不能完成而新版本完成的案例，按能力提升报告，不与基线失败所用时间直接作“加速倍数”比较。
6. 预算不因角色移动或子任务重建失效，失败情形保持有界，受影响正常导航与采矿回归通过。
7. 没有通过自然测试的新增能力明确标记为未验收；构建/测试未运行或卡住不能标记通过。
