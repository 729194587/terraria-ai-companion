# 开荒外出和工作台验收记录

2026-11-27 的隔离专服记录，包含当时的基线、失败尝试和复验结果。阶段状态及后续安排见[开发路线图](../DEVELOPMENT_ROADMAP.md)。

## 第一阶段：完成一次有收获的开荒外出

玩家只交代目的：“我们刚开荒，出去找点用得上的东西，拿到后再探一段。”同伴自行选择方向、目标和取物方式。宝箱、矿物和地面掉落都可以构成合理收获。用这个场景检验观察、判断和原生动作能否接起来。

| 已有证据 | 能说明什么 |
|---|---|
| 自然世界中只给“去附近探索”，外脑走了约 71 格，收到宝箱坐标并报告，导航超时后结束。 | 已验证能发现和报告。单次选择不足以判断角色缺少哪一条游戏知识。 |
| 同一世界明确要求找箱、取一件有用的东西并续行，外脑自行选了雨伞，专服确认入包，随后向右再走约 111 格。 | 已验证角色能够执行指定的取物方式。第一阶段进一步考察角色自己选择目标的能力。 |

**验证方式**是让新的外置大脑通过 MCP 从固定自然世界的出生点出发。两个世界使用相同原话，不给路线、物品、工具或步骤提示。核对角色收到的线索、自己选的目标、背包实际新增和取物后的新探索位移。角色若遇险或受阻，单独记下原因与终态。

**通过条件**是在两个固定自然世界中各完成一次：角色自行取得一项能说明开荒用途的物品，背包变化有专服证据，随后实际探索了新的地段。两个世界分别报告结果和 NPC 设置。受阻的运行保留在记录中。第一阶段用外脑验证，内置模型的付费回归留到用户决定启用时。

**2026-11-27 验收通过。** 两个外脑各自从出生点开始，背包里只有初始铜工具。专服使用自然地形副本，两个世界都关闭了非城镇 NPC。下表时间从发出玩家指令起算，首次入包取约每两秒一次的专服背包采样，总耗时取外脑最终答复。地图增量是从首次入包到结束时的 AiMap 已知格数差。

**采矿复查（同世界副本，脚本驱动专服）**

- 锡矿摘要已给出实测矿格 `targetTile=(2176,291)`。在原探索落点调用 `mine_target` 后，专服识别出 3 格锡矿，随后因搜索窗口内没有采矿方案而停止。原摘要的 `anchor=(2175,291)` 落在泥土上。
- 铜矿 `(2117,241)` 有 6 格。出生点旁的 `Terraria/Plants` 触发了局部清障规划器的地形拒绝，备选的 29 个地表站位均够不到矿。在仅允许移动预测穿过该普通植物的诊断包中，从出生点直接采矿仍耗尽路线搜索预算。先用原生导航到矿脉上方，再用同一铜镐采矿，专服确认清除 7 格障碍并挖完 6 格铜矿。原规划器从同一上方站位重试时仍被一株普通植物挡住。后续规划器回归可从出生点用一次采矿调用检验“先接近，再清障”。

铜矿回归的复验条件是从原世界出生点提交一次 `mine_target`，由规划器自行接近并清障，核对 6 格铜矿的原生破坏记录和矿石入包数量。上面的分步诊断仍单独计分。

后续复验先重放原场景，再换另一个世界。线索没有送达时查观察与摘要，选对动作却做不到时用固定脚本重放导航或交互。[探索实现与离线验收](../architecture/R3_AUTONOMOUS_EXPLORATION_IMPLEMENTATION.md) · [原生动作基准的覆盖范围](../BENCHMARK_PHASE1.md)

### 2C 满包反馈基线与复验（2026-11-27）

固定 MCP 脚本连接专服副本，使用与 2B 复验相同的 Mod 包。箱子在 `(2104,217)`，有 9 个木材。角色普通物品栏已满，其中一组木材还可叠 2 个。第一次“全部拿取”实际入包 2 个，MCP 的 `lastAction` 返回 `container_batch_partial`；原箱再取一次，入包 0 个，返回 `container_batch_blocked`。两次的 `blocked` 都报告槽 0 剩 7 个，原因是 `capacity_or_stacking_rule`。脚本把一组石块存入旁边另一个箱子，回到原箱再取，7 个全部入包，原箱剩余 0 个。

基线包的宝箱回执中，`blocked` 只有槽位、余量和原因。外脑需重新检查原箱来辨认剩余物品。

基线包的地面用例中，角色路过 7 个木材，已有的一组由 9996 增至 9999，余下 4 个仍在地上。MCP 没有收到漏捡提醒。腾出一格并回到物品位置仍未立即补捡。定点检查确认角色已接触木材、背包可容纳，掉落物当时无主，测试夹具设置的 1800 次更新保留计时仍有余量。

**2C 复验通过。** 两组固定 MCP 脚本分别在专服副本运行，各带两个协议观察客户端。地面 7 个木材能全部叠入时没有满包事件，只能叠 3 个时收到一次提醒，写明实收 3 个、地面余 4 个及掉落格坐标。腾出空槽、返回掉落位置并等到原生归属计时结束，背包木材从 9999 增至 10003。下一轮完全装不下 7 个木材时收到新的提醒。宝箱的可叠入、部分取出、完全受阻三种情况分别实收 2、2、0 个。后两次回执都给出原箱坐标、剩余 7 个木材及容量原因。存放一组石块后从原箱补拿 7 个，箱中余量为 0。测试通过专服数量和外脑可见的事件或回执验收。[固定脚本](../../tests/native_pickup_feedback.py)

复验入口为 `tests/verify_server_ai_container_native.py --pickup-feedback`，地面用例加 `--collect`，宝箱用例加 `--batches`，并提供 `--world` 和 `--package`。两组均通过真实 MCP 会话执行，无需调用模型。

### 3A 做出第一个工作台（2026-11-27）

固定 MCP 脚本在同一专服世界副本、同一绑定角色上运行两场。每场准备一棵由游戏生成的树、一把铜斧和初始木材，清空地面掉落物。脚本通过 `query_recipes` 读取当前工作台配方，对照背包决定是否砍树。缺料时从角色的局部观察取树干坐标。两场都核对原生制作回执、木材消耗、工作台入包及输入释放。[专服测试脚本](../../tests/native_first_workbench.py)

| 初始木材 | 配方和采集 | 制作前木材 | 实际消耗 | 制作后背包 |
|---:|---|---:|---:|---|
| 10 | 配方可用，直接制作 | 10 | 10 | 0 木材、1 工作台 |
| 7 | 配方缺 3，砍树并拾取 16 木材 | 23 | 10 | 13 木材、1 工作台 |

表中为首次实测。第二次运行时树掉落并入包 10 个木材，缺料场制作后剩 7 个木材，两场均再次制得工作台。从首个 MCP 工具开始到最终背包查询结束，直接制作耗时 3.9–4.1 秒（3 次 MCP 调用、5 次底层 API 调用），补料制作耗时 11.6–12.1 秒（5 次 MCP 调用、23 次底层 API 调用）。制作动作本身耗时 0.125–0.141 秒，铜斧砍树约 4.7 秒。计时含脚本分步取证，不含开服和模型推理。

复验入口为 `tests/verify_server_ai_direct_input_native.ps1 -TestScript native_first_workbench.py`，使用匹配的 `-PackagePath` 和 `-WorldPath`。固定脚本覆盖通过 MCP 查配方、补料和制作。外脑仅收到玩家原话时的自主决策尚未测试。

### 地下选路诊断（原 2B 实测，2026-11-27）

沿用 2A 的宿主和原生代码基线，关闭非城镇 NPC。为保证能观察角色面对洞口时的选择，在两个原始自然存档中各选了一个洞外地表起点。评测器事先用原生地形确认入口与两条支路有连通净空，并锁定判定区域。起点不在世界出生点，途中的地形保持自然生成。各世界的盲测与地下对照分别使用新的副本、初始铜工具和独立外脑，仅更换玩家原话。

| 自然世界种子与地表起点（格） | “我们开荒缺物资，去附近探索一下。” | “去附近调查地下，看看里面有什么。” |

四次外脑运行均收到 `possible_cave_entrance`，实际穿过了事前划定的入口，全程存活并安全释放控制权。盲测在两个入口区域分别新揭示 101、109 格。四次的轨迹都没有进入预定岔口，四次在两条支路的 AiMap 新增格数均为零。完成“附近找物资”与达到地下支路验收条件应分别记录。

**运动对照。** 两个世界都另用干净副本，从相同地表起点让固定脚本经 MCP 使用现有 `explore`。第一个世界重现向左超时，再调用两次向下、一次向右，轨迹穿过岔口并进入东侧支路，该支路新增 192 格。第二个世界在外脑停止的深度继续向下，再沿转弯后的通道向左，同样穿过岔口进入更深的西侧支路，该支路新增 164 格。两次均确认释放控制权。脚本预设了方向，这两条轨迹只用于验证至少一支可走。

共享光照采样后，在种子 `20261127` 的独立副本补测。角色从已核实的地下岔口出发，手持此前取得的荧光棒，无敌怪。独立外脑只收到“去附近探索”，自行查询现场后选择向左，沿西侧支路推进约 58 格、下降约 40 格，导航超时后结束。核对前后地图存档，西侧验收区域新增 338 格，上方支路的验收区域新增 127 格，角色轨迹没有进入上方支路。全程约 44 秒。外脑本轮未查持久地图或折返。另在隔离岔口用 MCP 脚本验证：走左路返回后，左侧落点为 `walked_nearby`，右侧为 `no_recent_visit`，后者仍有已知地形且可实际到达。

在同一个自然岔口，用世界、角色和初始地图相同的两个专服副本对照外脑工具说明。两次只下达“把附近几条路探清楚”。原说明组用时 120 秒，进入西侧支路后继续调查深层右岔。新增查图和脚印说明的一组用时 129 秒，进入西侧支路后，第 87 秒重新穿过出发岔口，随后走到起点以东约 64 格。两组都查了三次现场路线，都未调用持久地图查询，也均未走入预先划定的上方支路。时间从启动外脑算起，路线按角色脚下坐标核对。这一对观察只验证了外脑能自行折返换路，尚未验证主动查图。

**离开岔口后的盲测。** 在种子 `20261127` 的新副本中，先从原岔口沿西坡实走到脚下格 `(1746,328)`，再由新的外脑接手。它继承角色的地图和近期脚印，只收到“这附近还有没走过的路，去探一条。”预先选定的东侧路口已经离开实时视野，记忆里仍有 139 格已知空地，与岔口连通；上一次对照已有角色实际通过这里的轨迹。外脑读了一次现场路线，选中标为 `no_recent_visit` 的上方候选，随后调用一次 `explore(up)`。它沿西坡向回走了六段，37.7 秒后在 `(1770,301)` 附近报告已探过岔路。采样轨迹到来路的最大距离为 2.3 格，距所选候选落点最近仍约 7.8 格。调查范围新增 23 格，原岔口和东侧支路新增均为零；角色全程存活，释放已确认。此次未查持久地图，也未实走另一条新路。

`visitState` 描述一个候选落点，`explore(up)` 则独立选择逐段向上的落点。另用独立副本沿原路走回相同的像素起点，把所选候选 `(1742,320)` 直接交给 `navigate_to`。原生规划回执没有确认完整移动路线，57.3 秒后以 `navigation_progress_lease_expired` 超时结束，未确认到达，输入已释放。第一次尝试将角色直接放在坡上时夹具拒绝初态，该次未运行导航。这一对照验证了“所指落点能否到达”和“是否进入新路线”需要分别核对。地表出发的两世界物资盲测仍是 2B 的正式验收。
