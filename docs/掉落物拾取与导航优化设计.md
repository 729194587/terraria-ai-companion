# 掉落物拾取与导航优化设计

## 1. 优化目标

优化掉落物拾取与导航系统，使 Agent
能够在复杂地形中持续移动，并高效收集沿途及附近的掉落物。

本次包含两个相互关联的方向：

1.  **区域收集**：从逐个追逐最近物品，改为以区域为单位持续收集。
2.  **连续导航**：提升复杂地形下的搜索、路线衔接和移动能力，让规划器更充分地利用游戏中实际可行的路线。

核心原则：

**导航的职责是帮助玩家抵达目的地，而不是因为规划器能力不足，就把游戏世界的一部分判定为不可通行。**

拾取过程优先利用 Terraria 原生物品拾取机制。

## 2. 现有实现与主要问题

以下现状来自已审查的 `terrabot.zip` 源码快照。

### 2.1 掉落物拾取

当前实现：

-   `BotPerception.FindNearestDrops()` 扫描半径为 1800px。
-   `BotBrain` 在最近物品距离不超过 720px 时进入 Collect 状态，并通过
    `MoveToward()` 接近物品。
-   Autonomy 使用另一套收集流程，距离限制为 240px，并单独检查背包容量。
-   `BotPickupPolicy` 负责拾取资格判断。

主要问题：

-   普通收集与 Autonomy 的距离、容量判断不统一。
-   收集主要围绕最近单件物品展开，缺少区域级规划。
-   接近物品时没有充分利用原生拾取范围和现有导航能力。
-   物品移动、消失或无法拾取后，目标更新与恢复效率有待提高。

### 2.2 导航系统

当前实现包含局部 A\*、支撑面搜索和宽范围绕行机制。主要边界包括：

-   A\* 展开及支撑面节点上限为 40,000。
-   局部水平扫描宽度上限为 400 格。
-   搜索按游戏更新分配有限 work。
-   普通状态最大下降距离为 16 格，拥有免摔伤能力或翅膀时为 48 格。
-   `BotWideNavigation` 提供额外的宽范围搜索能力。

主要问题：

-   搜索范围和预算会限制复杂地形下的路线发现。
-   搜索未完成、移动模型不适用和确认无路可走，需要有清晰的结果区分。
-   固定移动能力分类和下落高度限制，尚不能完整表达角色的实际移动与生存能力。
-   进度判断需要综合水平、垂直移动和绕行过程。

## 3. 掉落物拾取优化

### 3.1 统一拾取候选判断

统一普通收集与 Autonomy 的候选物品判断，综合考虑：

-   物品有效性、拾取冷却及 Terraria 原生拾取规则。
-   个人掉落物归属。
-   背包空位与可堆叠空间。
-   当前行为优先级。

感知范围和实际收集范围可以承担不同职责，但应使用一致的候选判断规则。

### 3.2 区域清扫

将附近有效掉落物组织成一组收集目标，根据空间分布规划连续清扫路线：

1.  扫描并筛选有效掉落物。
2.  根据位置和拾取范围组织收集区域。
3.  选择能够覆盖多个物品的路线或站位。
4.  移动过程中利用 Terraria 原生机制拾取沿途物品。
5.  根据实际拾取结果更新目标集合。
6.  继续处理剩余区域，直至完成或达到任务结束条件。

收集规划以减少重复导航、提高单次移动的收集效率为主要目标。

### 3.3 原生拾取范围与结果确认

以角色进入物品原生拾取范围内的安全站位作为导航目标。站位判断结合角色和物品碰撞盒、实际拾取范围及地形阻挡。

收集结果根据实际拾取效果确认，并区分已收集、仍存在、已失效和暂时无法拾取的物品。背包无法容纳的物品应记录原因，让其他可收集目标继续推进。

## 4. 导航系统优化

### 4.1 搜索与可达性

明确区分完整路线、可继续推进的部分路线、预算耗尽、搜索范围不足、移动模型不适用和确认不可达等结果。

搜索尚未完成时，保留已有的有效搜索结果和可达前沿，为后续规划提供依据。

### 4.2 连续导航

借鉴 Numen 的 `Trip` 设计，将长距离导航组织为连续旅程：

1.  搜索并执行当前可用路线段。
2.  在执行期间继续规划后续路线。
3.  根据角色实际位置衔接下一段。
4.  地形变化或路线失效时重新规划。

单段搜索与整趟旅程分别管理预算和进度，使导航能够在合理资源范围内持续推进。

### 4.3 真实物理与下落安全

移动规划结合当前速度、重力、跳跃能力、翅膀、装备状态、碰撞盒及地形形状，确保路线能够由
Terraria 原生物理执行。

下落路线根据实际高度和生存能力评估，综合考虑：

-   原生摔落伤害与当前生命值。
-   免摔伤能力及相关装备。
-   液体环境和落点效果。

将预期伤害纳入路线风险评估，使规划结果更符合角色的实际承受能力。液体及特殊落点效果以游戏原生物理验证为准。

### 4.4 进度与失败恢复

根据实际位置、路径点变化、水平和垂直移动、路线段完成情况综合判断进度。

移动边执行失败后，记录失败原因并重新评估可选路线；地形或角色能力变化时，允许重新验证相关路线。

## 5. 拾取与导航的协作

拾取系统负责确定收集目标和区域完成情况，导航系统负责抵达可继续收集的位置，Terraria
原生机制负责完成拾取。

整体流程：

**扫描掉落物 → 筛选候选 → 组织收集区域 → 规划连续路线 →
执行移动与原生拾取 → 更新收集结果 → 继续清扫或结束任务**

导航暂时无法推进时，保留未完成目标，并根据搜索状态和移动能力选择后续处理方式。

## 6. 验收标准

### 拾取

-   [ ] 普通收集与 Autonomy 使用一致的候选判断规则。
-   [ ] 能够按区域组织掉落物，一条路线可以收集多个物品。
-   [ ] 导航目标考虑原生拾取范围和安全站位。
-   [ ] 物品移动、消失或失去拾取资格后，目标集合能够及时更新。
-   [ ] 背包容量不足时能够记录原因并继续处理其他目标。
-   [ ] 收集结果以实际拾取效果为准。

### 导航

-   [ ] 能够区分预算耗尽、范围不足、模型不适用和确认不可达。
-   [ ] 长距离任务能够分段规划并连续执行。
-   [ ] 能够根据实际移动能力规划跳跃、飞行和下落。
-   [ ] 下落路线能够结合预期伤害和角色生存能力评估。
-   [ ] 水平、垂直移动及合理绕行均能正确反映在进度中。
-   [ ] 路线执行失败后能够重新评估并尝试其他路线。

## 7. 参考实现

### Numen

GitHub：`Dwinovo/minecraft-numen`，1.21.1 分支。

重点参考：

-   `ItemReach`：原生拾取范围作为导航目标。
-   `MoveToCompanionTask`：最后接近阶段。
-   `Allowance`、`Trip`：分段搜索预算与连续导航。

### TerraBot

资料库：`terrabot.zip`。

重点参考：

-   `BotPerception.cs`：掉落物感知。
-   `BotBrain.cs`、`BotAutonomy.cs`：收集行为。
-   `BotPickupPolicy.cs`：拾取资格。
-   `BotNavigation.cs`、`BotNavigationWork.cs`：局部导航与搜索预算。
-   `BotWideNavigation.cs`：宽范围绕行。

参考项目用于借鉴设计思路，具体实现以当前项目的代码结构和 Terraria
原生物理为准。

## 8. 最终目标

将掉落物拾取升级为区域清扫，将导航升级为能够持续推进的连续旅程。

**拾取系统决定收集目标，导航系统负责抵达，Terraria
原生机制完成拾取，实际游戏状态决定任务是否完成。**
